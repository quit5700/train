# BUG-068：跨版本读取旧线路时选择错误存档，车辆段方块实体未声明模型渲染

- 类型：数据保存 / 读取问题、版本适配问题、方块模型问题
- 状态：`0.2.36` 已修复代码，待游戏内验收

## 1. 问题现象

在不同 Minecraft（我的世界）版本打开同一世界后，旧线路、车站、道岔或车辆段可能消失或恢复成较早状态。1.20.1、1.20.4、1.21.1 等版本的车辆段还会显示为空白、错误方块或不完整模型。

## 2. 根本原因

旧版本 SavedData（世界存档数据）使用 `world/data/fabric_train_simulator_railway_data.dat`，26.x 使用命名空间路径 `world/dimensions/minecraft/overworld/data/fabric_train_simulator/railway_data.dat`。两个文件并存时，各版本只读取自己的路径，可能读到较旧副本。

车辆段继承 `BaseEntityBlock（方块实体基类）`，但没有像发电机一样明确返回 `RenderShape.MODEL（模型渲染）`；部分版本不会稳定使用普通烘焙方块模型。

## 3. 修改文件

- 八个版本的 `RailwayDataMigration.java`、`FabricTrainMod.java`、`RailwaySavedData.java`
- 八个版本的 `TrainDepotBlock.java`
- `RailwayDataMigrationTest.java`、`TrainDepotRenderContractTest.java`
- `SUPPORTED_VERSIONS.md`、问题记录与回归清单

## 4. 具体修复方式

服务器读取 RailwaySavedData 前检查三种历史路径，选择最后修改且非空的线路存档。需要跨路径迁移时先生成 `.pre-0.2.36.bak` 一次性备份，再复制到当前版本的标准路径；不删除任何旧存档。存档新增 `SchemaVersion（结构版本）`，旧数据首次读取后自动补写版本号，并按现有设备、线路最大编号修复下一编号，避免旧计数器造成编号重复。

八个车辆段方块统一声明 `RenderShape.MODEL`，继续复用已存在的六面模型、朝向和贴图，不修改车辆段业务逻辑。

## 5. 如何验证

- `RailwayDataMigrationTest`：验证较新的旧路径文件迁移、备份保留、较旧文件不会覆盖较新标准文件。
- `TrainDepotRenderContractTest`：验证车辆段明确启用模型渲染且方块模型、方块状态资源存在。
- 八个版本完整执行 `clean build（清理并构建）`：共 1,896 项测试，0 失败、0 错误。
- 游戏内用旧世界分别进入 1.20.x、1.21.x 和 26.x，确认设备编号、线路节点及名称不变；检查世界目录生成备份文件；放置车辆段确认六面模型正常。

八个正式 JAR 与 sources JAR 已写入各自 `dist（分发目录）`；正式 JAR 已安装到指定测试客户端并通过 SHA-256（安全散列算法）一致性校验。旧 0.2.35 测试包保留为 `.disabled`，可恢复。

## 6. 下次应避免

不得只修改 SavedData 的资源标识而不提供跨路径迁移；不得在多个存档副本存在时固定读取其中一个。新增 `BaseEntityBlock` 时必须显式验证渲染形状。任何存档迁移必须先备份、不得删除来源文件，并用最大现有编号校正下一编号。

## 已尝试失败

- 只统一资源文件贴图不能修复车辆段，因为资源已正确打入 JAR，根因是方块渲染契约。
- 只给新字段提供默认值不能解决跨版本线路消失，因为两个 Minecraft 版本实际读取的是不同磁盘路径。
