# BUG-070：重建线路后重新进入世界，线路列表为空

- 类型：客户端与服务端环境问题、数据保存 / 读取问题
- 状态：`0.2.39` 已收紧正常存档读取策略，待玩家长期验收；原偶发现象根因未完全确认
- 影响版本：Minecraft（我的世界）`1.21.8`、`1.21.11`

## 1. 问题现象

玩家在铁路线路设置器中重建线路，退出并重新进入世界后线路不存在。真实主存档中 `Lines=0`，`NextLineId=1`。

## 2. 当前诊断结论

`0.2.39-diagnostic.1` 的一次完整实测证明：客户端创建、服务端接收、内存新增、SavedData（全局存档数据）序列化以及重启读取均成功，线路重启后仍存在。因此旧问题不是每次必现，原偶发根因仍不能仅凭这次成功日志确定。

`0.2.39` 将正常存档中的设备和线路登记明确作为权威来源。已有任一设备或线路时，登录不再启动区块扫描修改登记表；只有设备和线路都为空的旧存档才进入兼容恢复。临时诊断日志已移除。

## 3. 修改文件

- `mc1.21.8`、`mc1.21.11` 的 `DepotRemoteAccessSessions.java`
- `mc1.21.8`、`mc1.21.11` 的 `RailwayManagerNetworking.java`
- `mc1.21.8`、`mc1.21.11` 的 `DeviceRecoveryService.java`、`DeviceRecoveryPolicy.java`
- 两版 `DepotRemoteAccessSessionsTest.java`
- 两版 `DeviceRecoveryPolicyTest.java`
- 两版版本信息和版本号

## 4. 当前诊断方式

1. 仅为 `1.21.11` 制作 `0.2.39-diagnostic.1` 诊断版。
2. 使用统一的 `[DEBUG-RAILWAY-PERSIST-12111]` 日志标记记录客户端发送、服务端接收、授权结果、创建前后线路数、序列化线路数和重启读取线路数。
3. 不修改线路 NBT（命名二进制标签）结构、轨道、车辆或其他版本。

## 5. 验证结果与计划

- `1.21.11` 完整干净构建成功：240 项测试，0 失败，0 错误，0 跳过。
- 已生成普通 JAR 和 sources JAR（源码 Java 归档），并把诊断 JAR 安装到 `1.21.11-Fabric\mods`；分发文件与安装文件 SHA-256 均为 `1DE68ADF6F2485B644AD54A05201ED707F5D2335EBBAEABD17D762097F2F9693`。
- 玩家已执行一次“创建线路—退出世界—重新进入”，五阶段日志完整且线路仍存在。
- 新增 `DeviceRecoveryPolicyTest`，确认健康保存数据不会触发区块扫描，空旧存档仍可恢复。
- 仍需玩家在 `1.21.8` 和 `1.21.11` 对同一存档多次退出、进入后验收。

## 6. 下次应避免

不得让玩家可见设置窗口对应的合法编辑请求被静默丢弃。远程设置授权必须由服务端开窗统一建立，并为仍持有专用工具的玩家提供受限恢复路径。

## 已尝试失败

- 独立服务端自动持久化探针未运行到游戏阶段：开发运行配置中的 Fabric Data Generation API（Fabric 数据生成接口）命名空间与开发环境不匹配。该结果不能用于判断线路存档是否正常。
- `0.2.38` 的管理授权恢复方案：玩家在 `1.21.11` 实测后线路重启仍然消失，因此该方案不是已证实根因，不得重复作为最终修复。
