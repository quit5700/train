# BUG-045：重复道岔环线验证、固定出口路由与设置窗口回归

## 1. 问题类型

核心逻辑 / 线路验证 / 数据保存 / 客户端界面问题

## 2. 问题现象

线路按“道岔1直行、站点1、道岔2右转、站点2、道岔1左转、回收车辆段”配置且实际铁轨完整，立即发车仍提示节点之间断轨。同一道岔第二次经过时，列车方向还可能按当前行驶朝向旋转，而不是使用相对于固定车辆段入口保存的左转状态。首尾同一道岔的线路不被识别为循环线路。车辆段继续增加控件后，小窗口容易再次裁切底部内容。

## 3. 根本原因

`WorldLineValidator（世界线路验证器）`只读取世界中道岔方块当时唯一的 `RailShape（铁轨形状）`，没有读取线路节点序号对应的独立方向。同一物理道岔在节点表中出现两次时，一个方块形状不可能同时表达两次经过的不同出口。

运行控制器调用按列车当前朝向解释左转/直行/右转的方法，与已经确定的“相对于道岔固定入口保存状态”语义不一致。循环判断先过滤全部车站再比较首末车站，既漏掉道岔闭环，也没有比较线路表真实首末节点。响应式布局只接入车站和车辆段两个窗口，车辆段的编组汇总在紧凑模式中还会被隐藏。

## 4. 修改文件

- `WorldLineValidator.java`、`SwitchRailRouting.java`、`LineLoopRules.java`
- `TrainControllerManager.java`、`AutomaticLinePauseRules.java`
- `DepotNetworking.java`、`DepotSettingsAction.java`
- `ResponsiveScreenLayout.java`及七个自定义 `Screen（窗口）`
- 八个语言文件、README、VERSION_INFO及对应回归测试

## 5. 具体修复方式

线路验证逐段读取源节点在当前序号保存的道岔方向。源节点是道岔时，使用方块持久化的固定入口把左转/直行/右转换算成绝对出口；到达目标道岔不再受该方块当时显示形状限制。运行时根据列车实际进入侧和固定选择出口生成本次真实轨道形状，选择出口等于进入侧时安全停车并释放占用锁。

循环线路改为严格比较线路表第一个和最后一个节点编号，且闭环锚点只能是车站或道岔。到达末节点后从第二节点继续。车辆段暂停按钮把线路持久状态设为暂停，停止新自动发车；既有自动列车到下一站后保留停车计时，继续时统一释放。手动列车不读取此规则。

全部自定义窗口接入同一个宽高响应式布局。车辆段把暂停和保存固定在底部，中间内容滚动，并逐节显示有序车厢类型。立即发车失败会显示具体失败节点区段。

## 6. 验证方式

- 单元测试覆盖固定入口在不同进入侧仍选择同一绝对出口、无效回头出口、首尾同车站、首尾同道岔、真实首尾不同不得误判、车辆段不得作为闭环锚点、自动暂停与手动列车隔离。
- 源码接入测试覆盖逐段读取 `line.switchDirection(i - 1)`、七个窗口统一响应式布局、车辆段有序车厢显示及暂停操作不触发发车。
- 在 UTF-8 中文路径中执行定向测试和完整 `gradlew test`，均成功。
- 仍需在 Minecraft（我的世界）中用用户截图对应的双道岔环线验证立即发车、第二次经过道岔1左转、下一站暂停、继续运行和小窗口滚动。

## 7. 下次避免

线路节点保存的是“每次经过”的业务状态，禁止用世界方块某一时刻的单一物理状态代替。道岔方向必须明确区分固定入口、绝对出口和列车进入侧。新增任何窗口控件必须放入响应式内容区或固定底部区，不得再增加固定窗口高度后只靠人工调坐标。

## 已尝试失败

- 仅按道岔当前 `RailShape（铁轨形状）`验证整条线路：已失败，不得恢复。
- 按列车当前行驶朝向重新解释左转/直行/右转：已失败，不得恢复。
- 过滤全部车站后比较首末车站判断循环：已失败，不得恢复。
- 只给当前新增窗口加固定高度和坐标：已失败，不得恢复。
