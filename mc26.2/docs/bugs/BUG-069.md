# BUG-069：旧世界区块仍有设备，但线路设置器为空

- 类型：数据保存 / 读取问题、旧版本 API 迁移问题
- 状态：`0.2.37` 已修复代码，待游戏内验收

## 1. 问题现象

1.21.11 等版本的世界中仍能看到车站、道岔和车辆段方块，但打开铁路线路设置器时三列为空。

## 2. 根本原因

Minecraft（我的世界）区块文件和 SavedData（全局存档数据）是两层独立数据。旧方块还在区块里，但对应的 `Devices`、`Lines` 列表已是空的；旧方块被加载时不会再执行“放置方块”注册逻辑。此外，0.2.36 只按修改时间选数据文件，较新的空存档可能压过较旧的有效备份。

## 3. 修改文件

- 八个版本的 `DeviceRecoveryService.java`、`RegionDeviceChunkScanner.java`
- 八个版本的 `RailwayDataMigration.java`、`FabricTrainMod.java`、`RailwayManagerNetworking.java`
- `RailwayDataMigrationTest.java`、`RegionDeviceChunkScannerTest.java`
- 版本说明、BUG 索引和回归清单

## 4. 具体修复方式

1. 迁移器解析 NBT（命名二进制标签）中真实的 `Devices` 和 `Lines` 数量，先按有效内容、再按修改时间选择存档。
2. 纳入扁平路径、命名空间路径、旧备份、`dat_old` 和恢复备份；有效存档另存 `.recovery.bak`，新的空文件不得覆盖它。
3. 后台只读 Anvil Region（区域存档）头和压缩块数据，找出含本模组三种设备的候选区块。
4. 服务端每游戏刻最多加载一个候选区块，逐格确认真实方块后只补齐缺失的设备记录；不强制长期加载区块，不改已有设备编号和设置。
5. 文件路径全部由合法目录名构成，不把资源 ID 中的冒号当成 Windows 文件名。

## 5. 验证

- `RailwayDataMigrationTest`：较新空存档与较旧有效备份并存时，保留有设备/线路的文件。
- `RegionDeviceChunkScannerTest`：不加载 Minecraft 区块即可找出含车站的负坐标区域块。
- 八个版本的上述定向测试和 Java（爪哇）编译全部通过。

## 6. 下次应避免

不得把“文件非空”当成“业务数据非空”；不得只按文件时间选择 SavedData。不得依赖旧方块再次触发放置事件。不得在 Windows 路径中使用冒号资源 ID。

## 已尝试失败

- 0.2.36 “只选最新的非零字节文件”已证明不足：空 `Devices/Lines` 的 NBT 文件仍然有数百字节。
- 只恢复已加载区块会漏掉远处设备，因此改为先扫描磁盘区域文件、再限速加载候选区块。
