# BUG-031：碰撞编组反复失效，改用连接器显式连接

## 问题类型
核心逻辑问题 / 数据保存问题

## 1. 问题现象
客车、货车和火车头依靠碰撞自动连接时多次出现“有音效但没有形成有效编组”、已有车厢组无法被车头接管等问题，实际操作结果不稳定。

## 2. 根本原因
碰撞既承担原版矿车物理推动，又承担编组状态修改。碰撞方向、速度、同一游戏刻内的多实体接触和车头驻车状态会竞争修改速度及编组元数据，无法提供明确、可重复的玩家操作边界。

## 4. 具体修复方式
删除碰撞自动连接。新增连接器：左键第一辆车后物品高亮闪烁，在 16 格内左键第二辆车连接两个端点；选择同一编组中直接相邻的两辆车会在两车之间切断并拆成前后两个编组。连续左键同一辆车只取消选择，非相邻车辆不能断开。潜行右击已连接车辆打开编组管理窗口，可排序或解散整列。手持连接器时取消实体攻击伤害并禁止破坏方块。

车辆段改为检查两个铁轨出口：恰好只有一侧能通向车站或道岔时，该侧为前方，另一侧为后方；生成车辆后立即写入同一正式编组。手工解除连接只允许使用连接器，车辆段回收仍属于系统操作。

- `ConnectorRulesTest` 验证 16 格范围和最多 1 个火车头加 100 节车厢。
- `ConnectorActionRulesTest` 验证同车取消、异组连接、相邻断开和非相邻拒绝。
- `DepotDirectionRulesTest` 验证车辆段前后方判定。

## 6. 下次避免
不要再恢复碰撞自动连接，也不要把“点同一辆车两次”解释为拆车。连接关系的删除对象必须是两辆直接相邻车辆之间的边；编组修改必须经过服务端的单一连接服务，并对每次操作给出明确成功或失败结果。
