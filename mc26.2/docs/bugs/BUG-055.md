# BUG-055：自动停车候选端点导致线路运行异常

## 问题类型

核心逻辑 / 线路验证 / 数据保存问题。

## 问题现象

`0.2.21` 的线路可以正常运行；升级到 `0.2.22` 并刷新线路后，岔路、平行轨道或回环附近的运行路径发生混乱。

## 根本原因

`0.2.22` 为自动选择停车点，把车站周围 8 格内最多 32 格信号铁轨直接作为寻路候选端点，再使用 `scanAny（扫描任意终点）`选择最先到达的候选。候选端点参与了线路走向决定，可能在到达真正车站轨道前提前命中旁边分支；验证成功后还会覆盖原来正确的停车坐标。

## 修改文件

- `src/main/java/cn/quit5700/fabrictrain/route/WorldLineValidator.java`
- `src/main/java/cn/quit5700/fabrictrain/route/TrackPathScanner.java`
- `src/main/java/cn/quit5700/fabrictrain/route/StationStopTrackRules.java`
- 线路验证和站点停车规则回归测试、八种语言、版本文档。

## 具体修复方式

1. 站点方块坐标为 `(X,Y,Z)` 时，停车轨道只允许为正上方 `(X,Y+1,Z)` 的普通信号铁轨。
2. 线路每段恢复为准确起点到准确终点的单目标扫描。
3. 删除车站周围候选、候选评分、`scanAny`和整批覆盖停车坐标的代码。
4. 正上方不是普通信号铁轨时明确报告站点停车轨道无效。

## 已尝试失败

- `0.2.22` 的“车站周围候选铁轨 + 任意终点扫描 + 最近距离评分”已证实会改变线路，禁止再次采用。
- 旧版任意高度手动绑定停车轨道的规则已被最新需求“铁轨铺在站点方块正上方”取代。

## 如何验证

1. 在站点正上方铺本模组普通信号铁轨，附近另铺平行线和岔路；刷新后停车坐标必须始终为 `(X,Y+1,Z)`。
2. 使用在 `0.2.21` 正常的线路刷新并运行，线路节点顺序和道岔方向不得变化。
3. 移除站点正上方铁轨，立即发车应提示该站点正上方没有信号铁轨。

## 已执行验证

- 业务规则和源码契约定向测试通过；完整自动回归通过。
- 真实 Minecraft（我的世界）世界中的旧线路刷新仍待玩家验收。

## 下次遇到类似问题应避免什么

停车点只能描述列车在既定线路上的停靠位置，不能反过来作为多个候选端点改变线路拓扑。没有真实世界拓扑回归用例时，不得仅凭源码字符串检查声称路径选择正确。
