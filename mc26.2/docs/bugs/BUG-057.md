# BUG-057：坡道铁轨被误判断轨，长线路供电重复扫描

- 类型：核心逻辑 / 供电缓存 / 三维路径
- 状态：`0.2.24` 运动修复不完整；线路验证问题由 `BUG-062` 在 `0.2.26` 修复

## 1. 问题现象

线路出现不同高度后，列车会在坡道或高度变化处停止；长线路供电依赖已加载区块并每秒重扫，未加载区块可能被误当成未供电。

## 2. 根本原因

整列控制器用矿车实体的临时方块坐标猜测铁轨，而不是使用 Runtime Path Cursor（运行时路径游标）已确定的真实三维铁轨。供电服务没有线路分段快照，每次刷新都会重新遍历整个已加载网络。

## 3. 修改文件

- `train/RailPositionResolver.java`、`train/RailMotionCursor.java`、`train/TrainControllerManager.java`
- `power/RailPowerService.java`、`power/PowerSectionCache.java`、`power/PowerSectionSnapshot.java`
- `route/WorldLineValidator.java`、`route/RuntimePathCache.java`
- `block/SignalRailBlock.java`、`block/PowerGeneratorBlock.java`

## 4. 修复方式

列车优先读取游标的真实轨道；没有游标时才按当前位置、下方、上方恢复。线路验证后按每 64 格建立供电段；发车检查全部段，运行只检查当前段和下一段。供电改变只刷新受影响的轨道点，未加载区块保留上次验证状态。

## 5. 验证

`RailPositionResolverTest`、`TrainRailPositionContractTest`、`PowerSectionSnapshotTest` 和完整 `gradlew.bat test`。

## 6. 后续避免

不得再次从实体瞬时高度推测线路铁轨；不得恢复成每游戏刻或每秒完整扫描长线路的方案。

## 已尝试失败

`0.2.24` 修复了列车运动时的三维轨道游标，但没有修复创建或刷新线路时的坐标来源。线路验证仍误用矿车运动出口表，所以高处向低处的坡道仍会提示断轨。仅修改运动游标不得再作为此问题的完整修复。
