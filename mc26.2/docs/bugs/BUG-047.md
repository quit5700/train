# BUG-047：车站固定高度猜轨与旧手动卸货绕过目的地

## 1. 问题类型

核心逻辑、数据保存、线路验证、服务端货运和客户端界面问题。

## 2. 问题现象

车站旁实际信号铁轨完整，但只要铁轨与车站方块不在同一高度，线路验证就可能提示相邻节点之间轨道不完整。线路也不能明确表示“这一站具体停在哪一格”，同一车站重复出现在不同位置或不同高度时尤其容易误判。

车站原有“手动卸货”开关会按容器已有同类物品卸货，绕过火车头和每节货车的目的地规则。火车头选择货车类别时不能稳定保留空目的地；货车清空目的地的界面行为也不明确。

## 3. 根本原因

`WorldLineValidator（世界线路验证器）`把车站方块坐标临时当成轨道端点，只检查固定高度或水平邻近位置，没有把停车轨道作为线路节点自己的持久数据。运行时到站判断再次独立猜测，验证和运行没有共享同一个精确坐标。

旧 `StationManualUnloadService（车站手动卸货服务）`由车站布尔开关周期触发，与列车目的地规则并列存在。`TrainClassNetworking（列车类别网络服务）`又会把火车头目的地直接写入每节货车的独立字段，无法表达“货车空值继承火车头”和“货车独立覆盖”的区别。

## 5. 具体修复方式

`RailwayLine（铁路线路）`按节点序号保存 `stationStopTracks（车站停车轨道）`映射；线路排序、插入、删除和 NBT（命名二进制标签）存档同时维护该映射。验证、运行时到站和界面显示统一读取精确三维坐标。旧线路仅在车站半径 8 格三维范围内存在唯一最近的普通信号铁轨时自动迁移；否则返回独立的“停车轨道未绑定”原因。道岔不能绑定为停车轨道，停车格本身不修改铁轨形状、速度或驻车锁。

线路设置器选中站点节点后进入一次绑定状态，下一次点击普通信号铁轨即保存；手持设置器时服务端只向该玩家发送粒子高亮。车站存在性检查只读取已经保存的绑定，不在卸货周期中偷偷修改线路。

车站手动卸货开关从界面和服务器周期服务中移除。有效目的地统一为“货车独立目的地大于 0 时优先，否则继承火车头默认目的地”；两者都可为空。火车头目的地实际变化时，清空同编组货车的独立目的地。货车窗口提供明确的空选项和“全部卸货”按钮；普通到站卸货只在有效目的地匹配且车站连接容器时发生，全部卸货只作用于玩家点击的当前货车。

## 7. 下次遇到类似问题应避免什么

线路业务节点不能靠每次运行时猜测附近方块来补足关键坐标；会影响寻路和停车的坐标必须进入线路持久数据，并由验证、运行和界面共用。卸货只能有一个规则入口，不能让车站开关和列车目的地分别触发两套互相绕过的服务。空值、继承值和独立覆盖值必须用不同字段语义表达，不能在连接时把默认值复制成独立值。

## 已尝试失败

- 按车站方块同一 Y 坐标或水平相邻位置寻找停车铁轨：已失败，禁止恢复。
- 保留车站手动卸货周期服务并同时增加列车目的地判断：会产生两套触发入口，已废弃。
- 用 Flat Directory（平面目录）只加载 Fabric Loom 主 JAR 离线构建：缺少 Gson 等传递依赖，不能作为正式构建方式。
