# BUG-051：自动道岔与手动方向干扰、车辆段操作无反馈和历史列车残留

## 类型

核心逻辑 / 数据保存 / 客户端界面问题。

## 问题现象

1. 线路自动列车要求的出口与道岔可见手动方向不同时，在道岔前和道岔上长时间等待。
2. 增加“列车列表”后，车辆段的保存、暂停/继续、立即生成和立即发车看起来没有反应；保存后窗口关闭，列车列表也无法稳定返回。
3. 已回收、脱轨掉落或删除的列车仍长期显示在列车列表，并可能残留在轨计数和道岔锁。

## 根本原因

1. `0.2.18` 仍将自动线路方向写入现场 `RailShape（铁轨形状）`，再在尾车离开后恢复手动方向。两种运行模式共用了一个可变形状，所以线路缓存正确也会被现场形状阻塞。
2. 保存动作在发送数据后直接关闭客户端窗口；服务端动作只发聊天消息，没有把新状态和结果重新发回设置窗口。列车列表负载中也没有车辆段坐标，返回时不能精确重开原车辆段。
3. 列车注册表只会增加身份。部分移除路径只删了在轨计数，没有统一清理道岔锁、运行缓存和可见注册状态。

## 具体修复方式

1. 保留可见左转/直行/右转作为纯手动列车状态。线路自动列车从 `Runtime Path Cache（运行时路径缓存）`取道岔前后坐标，由整列逻辑控制器沿隐形路径移动，不再写入或恢复道岔的可见形状。两种模式仅共享防碰的占用锁。
2. 所有车辆段动作执行后，服务端带操作结果重发完整设置数据；客户端重建并保持设置窗口，在固定底部显示结果。列车列表携带原车辆段坐标，“返回”精确重开它。
3. 增加统一的列车资源注销入口。正常回收、脱轨掉落、创造模式删除和整列销毁会清理在轨计数、道岔锁、运行缓存与可见列车状态。`RemovalReason.shouldDestroy（移除原因是否销毁）` 为假的区块卸载不触发注销。
4. 旧存档中缺少 `Present（当前存在）` 标志的记录先隐藏为历史身份；对应实体区块加载后，用原 UUID（通用唯一识别码）重新激活同一编号。

## 已尝试失败

- 自动列车通过前临时改动道岔 `RailShape（铁轨形状）`，尾车离开后再恢复手动方向：实际环线中仍会互相覆盖并长时间等待，禁止重复使用。
- 仅从列车表中删除记录而不保留编号身份：未加载区块中的真实列车会在重新加载时获得新编号，不得使用。

## 如何验证

1. 手动把道岔设为与线路要求不同的方向，立即发车；自动列车应按线路缓存直接通过，道岔外观始终保持手动方向。
2. 在车辆段依次测试保存、暂停/继续、立即生成和立即发车；窗口应保持打开，底部应显示对应结果。进入列车列表后点击返回，应回到同一车辆段。
3. 回收、脱轨掉落和创造模式删除列车，下一游戏刻后确认列车列表与在轨计数中消失，同一道岔可由后续列车使用。
4. 保存一列在已卸载区块中的列车并重启，列车不得因区块卸载被注销；区块重载后列车编号不变。

## 下次遇到类似问题应避免什么

手动状态和线路自动路由必须是两个独立数据源，不得再使用“临时改现场状态，之后再恢复”的方案。列车的游戏实体、在轨数、占用锁、运行缓存和列表可见性必须使用同一个生命周期入口改变。
