# BUG-043：发车车辆段与回收车辆段被同一字段混用

## 1. 问题类型

数据保存 / 服务端发车逻辑问题

## 2. 问题现象

玩家已经创建线路，但车辆段设置中的线路选择框选不到该线路，车辆段也无法按所选线路发车。
把车辆段拖入线路节点后，编辑节点顺序又会改变线路保存的车辆段编号，发车职责和回收职责互相覆盖。

## 3. 根本原因

`RailwayLine.depotId（线路车辆段编号）`同时承担“负责生成列车的发车车辆段”和“线路节点中的回收
车辆段”两种含义。`insertLineNode（插入节点）`与 `modifyLineNode（修改节点）`每次都从节点列表重新
推导该字段，导致显式发车选择无法独立保存。车辆段设置窗口还只列出“首节点等于当前车辆段”的线路，
而用户创建的新线路最初并不满足这个过滤条件，所以界面看起来根本无法选择线路。

## 5. 修复方式

保留存档字段 `DepotId（车辆段编号）`，但将其唯一含义固定为“发车车辆段”；回收车辆段改为从线路
节点列表中唯一的 `DEPOT（车辆段）`节点派生。节点增删、移动不再修改发车绑定，且一条线路最多加入
一个回收车辆段。两者允许是同一个方块。

新增统一的服务端绑定操作：一个车辆段只能绑定一条发车线路；新车辆段绑定同一线路会自动解除旧
发车车辆段；改绑其他线路时旧线路也自动解除；选择编号 0 即“未选择线路”。车辆段方块窗口和线路
设置器中的车辆段设置都经过同一个 `DepotNetworking（车辆段网络服务）`入口，窗口列出全部线路。

选择了线路的立即发车和定时发车都会扫描从发车车辆段上方铁轨到线路首个不同节点的路径，确认路径
完整且每格已通电，并使用扫描路径的第一步确定出车方向。线路终点回收、脱轨回收和重启回收均读取
节点列表中的唯一回收车辆段，不再误用发车车辆段。

  的 SHA-256 完全一致；0.2.9 已移动到独立备份目录。

## 7. 下次避免

同一编号字段不得同时表示“配置归属”和“路线节点”。界面选择条件必须来自明确的服务端关系，不能
从节点位置猜测。任何会影响自动发车的绑定修改，都必须有双向唯一性测试和旧绑定清理测试。
