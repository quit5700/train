# BUG-036：Minecraft 26.2 客户端输入接口与旧版写法不兼容

## 问题类型

版本适配问题 / Yarn Mappings（Yarn 命名映射）问题

## 问题现象

车辆段速度输入框与 `Ctrl（控制键）+右键`入口首次编译失败：`EditBox.setFilter` 和
`Screen.hasControlDown` 在 Minecraft 26.2（我的世界 26.2）中不存在。

## 根本原因

误用了旧版本 Minecraft（我的世界）的客户端界面辅助方法。26.2 的 `EditBox（输入框）`
仅提供响应器和格式化器接口；控制键状态需要通过 `InputConstants（输入常量）`和当前
`Window（窗口）`读取。

## 已尝试失败

- `EditBox.setFilter(...)`：26.2 无此方法。
- `Screen.hasControlDown()`：26.2 无此方法。
- 仅在 `FabricTrainClient（Fabric 火车客户端入口）`中追加第二个
  `UseBlockCallback（使用方块回调）`：能够编译，但在含多个交互模组的实际整合包中，
  该回调可能被先注册的其他回调提前截断。运行时修复已转入 `BUG-039`。

## 修改文件

- `src/client/java/cn/quit5700/fabrictrain/client/DepotSettingsScreen.java`
- `src/client/java/cn/quit5700/fabrictrain/FabricTrainClient.java`

## 修复方式

- 删除不存在的输入过滤器，保留服务端速度合法性校验，并在提交时安全解析。
- 使用 `InputConstants.isKeyDown(window, KEY_LCONTROL/KEY_RCONTROL)`检测左右控制键。

## 验证

执行 `gradlew.bat compileJava compileTestJava --no-daemon`，编译成功。

## 后续避免

Minecraft 26.x（我的世界 26 系列）的客户端输入方法必须先通过当前映射 JAR 的
`javap` 或已编译代码确认，不得直接套用旧版 `Screen`、`EditBox`静态辅助方法。
同时不能把“编译成功”等同于整合包事件顺序已经正确，交互入口必须检查注册阶段和回调优先顺序。
