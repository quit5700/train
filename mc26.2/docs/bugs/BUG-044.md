# BUG-044：车辆段操作混用、发车方向错误与道岔永久停车

## 1. 问题类型

核心逻辑 / 数据保存 / 客户端界面问题

## 2. 问题现象

车辆段只有一个同时保存并发车的操作，选择线路重新打开又可能显示未选择；无线路或线路入口判断错误时列车向错误方向生成。手动列车会停在四向道岔前一格且无法继续。车站也没有线路自动货车专用的停靠时间。

## 3. 根本原因

`UpdatePayload（更新数据包）`只用布尔值区分发车，服务端不论操作类型都先覆盖方块设置。定时调度只看已选线路，没有“已经由成功立即发车启动”的持久状态。发车方向仍使用旧 64 格单向猜测，绑定线路还错误要求发车车辆段编号与线路旧字段完全一致。道岔控制器取得占用锁后，如果选择出口没有有效铁轨就直接返回，遗漏释放锁。

## 4. 修改文件

- `DepotNetworking.java`、`DepotSettingsScreen.java`

- `WorldLineValidator.java`、`DepotDirectionRules.java`

- 八个语言文件及对应回归测试

## 5. 具体修复方式

把车辆段操作改为保存、立即生成手动列车、立即发出自动列车三种服务端动作。只有保存写入配置；只有自动列车成功发出后才持久启用定时调度并重置计时。发车路径从车辆段上方铁轨的两侧分别扫描至线路首个不同节点，选择唯一或更短的有效路径，扫描最多 20000 格且不强制加载区块。线路删除统一经过服务端删除服务，手动列车保持不变。

道岔所选出口无效时立即释放本列车刚取得的占用锁。车站存档增加默认 120 秒的货车停靠时间；旧存档缺少字段时自动采用默认值。线路自动货车读取该值，手动列车到站只停车和卸货，不建立自动恢复计时。

## 6. 验证方式

- 单元测试覆盖货车/客车停靠时间选择、两侧方向距离规则和三个车辆段操作的源码契约。
- 在 UTF-8 中文路径中运行 `gradlew test` 成功。
- 最终还需在游戏中逐项验证立即生成、立即发车、重启后调度、长距离两侧方向、交叉道岔再次通行和线路删除后的自动列车回收。

## 7. 下次避免

禁止再用一个布尔字段混合“保存配置”和“执行一次动作”。取得独占锁后的每条失败路径必须成对释放。业务停靠规则必须按 `ControlMode（控制模式）`和车型明确区分，不能让手动列车复用自动恢复计时器。

## 已尝试失败

- 64 格内只判断“是否存在设备”的发车方向猜测：已失败，不得恢复。
- 无条件在立即发车前保存窗口状态：已失败，不得恢复。
- 道岔出口无效时保留占用锁：已失败，不得恢复。

## 2026-08-02 0.2.12 重新打开与修复

### 问题现象

- 0.2.11 后仍有一个道岔无法释放占用锁。
- GUI Scale（界面缩放）较大时，站点卸货按钮、站点保存按钮和车辆段保存按钮超出屏幕。
- 已选择线路且在轨数量为 `0/5`时，“立即发车”仍错误提示“需要选择有效线路或达到上限”。

### 根本原因

- 锁释放仍依赖下一个道岔，最后经过的道岔没有后续释放事件。
- 新增货车停靠时间和车辆段名称后，窗口内容固定高度增加到 304/318，未限制为实际逻辑屏幕高度。
- 服务端把线路非运行状态、线路不存在和达到上限合并为同一判断；截图中的线路实际属于 `NEEDS_VALIDATION（需要重新验证）`。

### 修复方式

- 使用 `SwitchPassageState（道岔通过状态）`记录“已经进入”和“尾车全部离开”，按列车与道岔分别保存；所有终止路径统一释放。
- 使用 `ResponsiveScreenLayout（响应式窗口布局）`限制面板高度，紧凑模式压缩间距，保存和卸货固定在底部，极小窗口提供滚轮偏移。
- 使用 `DepotDispatchPrecheck（车辆段发车预检查）`拆分所有状态。“需要重新验证”时即时刷新供电缓存、扫描完整线路与发车车辆段到首节点路径，成功后转为运行并继续发车；失败显示具体原因。立即发车仍不保存临时窗口值。

### 回归测试

- `SwitchPassageStateTest`覆盖未进入不得提前释放、尾车未离开不得释放、尾车离开立即释放。
- `ResponsiveScreenLayoutTest`覆盖 GUI Scale 4 对应的小逻辑高度、固定底部按钮和滚动区域边界。
- `DepotDispatchPrecheckTest`覆盖七种互斥结果；源码契约测试确认三套规则接入实际控制器、窗口和网络服务。
