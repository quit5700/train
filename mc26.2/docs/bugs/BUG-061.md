# BUG-061：车辆段列车列表混入手动列车和旧记录

- 类型：数据保存 / 实体生命周期 / 客户端与服务端
- 状态：`0.2.25` 的列表过滤规则已由 `BUG-067` 在 `0.2.33` 更新

## 1. 问题现象

车辆段未选线路时仍能打开列车列表；列表显示全局手动列车、其他线路自动列车，且重启后可能继续显示上次留下的已加载记录。

## 2. 根本原因

列表网络请求直接读取 `presentTrainRecords（全局存在列车）`，没有使用车辆段选定的线路编号和自动控制模式过滤。服务器启动只清空在轨计数，没有把当前存档格式中的旧 `LOADED（已加载）`记录改为待实体确认。

## 3. 修改文件

- `RailwaySavedData.java`
- `FabricTrainMod.java`
- `DepotNetworking.java`
- `DepotSettingsScreen.java`
- 八个 `lang（语言）` JSON 文件
- `TrainPresenceLifecycleTest.java`
- `DepotTrainListContractTest.java`

## 4. 修复方式

车辆段未选线路时禁用列表按钮，服务端也会校验并提示“请先选择线路”。服务端只返回 `lineId（线路编号）`匹配且控制模式为 `ROUTE_AUTOMATIC（线路自动）`的可见记录。服务器启动时将旧 `LOADED` 改为 `LEGACY_UNCONFIRMED（待确认）`，但保留 `UNLOADED（未加载）`和 `OFFLINE（离线运行）`。真实实体重新加载后使用原列车编号恢复。

## 5. 验证

`TrainPresenceLifecycleTest` 覆盖重启状态转换、未加载/离线保留、实体恢复原编号和按线路过滤；`DepotTrainListContractTest` 覆盖客户端禁用与服务端二次校验。

## 6. 下次避免

不得让车辆段的线路列表读全局注册表；服务器重启恢复必须区分已加载、未加载和离线运行，不得全清或全保留。

## 后续规则更新

用户后来明确要求车辆段列表同时显示有效手动列车与当前线路自动列车。`BUG-067` 使用持久成员 UUID 排除已销毁的手动列车，不再通过隐藏全部手动列车规避残留记录。
