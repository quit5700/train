# BUG-008：开发运行环境缺少完整 Fabric API

## 问题现象

实际启动客户端时，Fabric Loader（Fabric 模组加载器）在加载阶段报告本模组需要 `fabric-api >= 0.154.0+26.2`，但运行环境没有该模组。

## 根本原因

为了缩短编译时间，构建只声明了用到的 Fabric API（Fabric 应用程序接口）拆分模块；它们不提供完整包的 `fabric-api` 模组标识，而 `fabric.mod.json` 正确声明的是用户安装时所需的完整 Fabric API。

## 修改文件

- `build.gradle`
- 本 BUG 记录与索引

## 具体修复方式

保留拆分模块作为编译依赖，同时增加指定版本完整 Fabric API 的 `runtimeOnly`（仅运行时依赖），使开发客户端与实际用户环境一致。

### 已尝试失败

尝试使用旧资料常见的 `modRuntimeOnly` 配置名，但当前 Fabric Loom 1.15.5（Fabric 构建插件）没有注册该配置，项目配置阶段即失败。不得再次采用该配置名。

## 如何验证

重新运行 `runClient`（启动客户端），检查到达主菜单且日志没有模组加载错误。

## 下次应避免

拆分 Fabric API 模块只能替代编译类路径，不能自动满足完整 `fabric-api` 模组标识的运行时依赖。
