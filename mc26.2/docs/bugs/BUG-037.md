# BUG-037：八语言校验命令误用 PowerShell 7 参数

## 问题类型

Windows PowerShell 兼容性问题 / 验证脚本问题

## 问题现象

八语言 JSON（JavaScript 对象表示法）校验使用 `ConvertFrom-Json -AsHashtable`，在当前
Windows PowerShell 5.1 中参数不存在；非终止错误又导致脚本错误输出“0 个文件通过”。

## 根本原因

`-AsHashtable` 是较新 PowerShell 的功能，且原命令未设置 `$ErrorActionPreference='Stop'`。

## 已尝试失败

- 在 Windows PowerShell 5.1 直接使用 `ConvertFrom-Json -AsHashtable`。
- 在未启用兼容 PCRE2（Perl 兼容正则表达式）的 `rg`中使用
  `IsCJKUnifiedIdeographs` Unicode 属性扫描中文字符。

## 修改范围与修复方式

本次未修改模组代码；校验命令改为遍历 `PSObject.Properties`构建哈希表，并启用错误立即
终止，禁止解析失败后继续报告成功。Java（爪哇）显示文字扫描改用 Windows PowerShell
5.1 正则表达式的 `[一-龥]`字符范围。

## 验证

重新校验得到 `LANG_OK files=8 keys=166`，八个语言文件键集合与 `%s`参数数量一致；
Java 显示文字扫描得到 `JAVA_VISIBLE_TEXT_OK`。

## 后续避免

项目 PowerShell 命令默认以 Windows PowerShell 5.1 为最低兼容版本；使用新版参数前必须
先确认 `$PSVersionTable.PSVersion`，验证脚本必须让解析错误立即失败。
