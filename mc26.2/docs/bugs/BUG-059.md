# BUG-059：列车列表残留已删除的手动列车

- 类型：数据保存 / 实体生命周期
- 状态：`0.2.24` 修复不完整，已由 `BUG-061` 在 `0.2.25` 重新修复

## 1. 问题现象

列车实体已经回收或删除，列车列表仍显示旧手动列车；同时不能把正常区块卸载误判为销毁。

## 2. 根本原因

旧格式只保存 `Present（存在）` 布尔值，无法区分已加载、未加载、离线、销毁和旧记录待确认；实体回调也只处理破坏，没有明确记录正常卸载。

## 3. 修改文件

`TrainPresence`、`TrainRecord`、`TrainRecordPresence`、`RailwaySavedData`、三种列车实体的移除回调和 `TrainControllerManager`。

## 4. 修复方式

列车状态改为 `LOADED（已加载）`、`UNLOADED（未加载）`、`OFFLINE（离线运行）`、`DESTROYED（已销毁）` 和 `LEGACY_UNCONFIRMED（旧记录待确认）`。旧格式升级时全部隐藏为待确认；仍存在的实体重新加载后以原编号恢复。最后一节真实车辆销毁时统一清理列表、在轨计数、道岔权、运行缓存和离线记录；普通区块卸载只变为未加载。

## 5. 验证

`TrainPresenceLifecycleTest`、`TrainLifecycleContractTest` 和完整 `gradlew.bat test`。

## 6. 后续避免

不得用单一布尔值同时表达实体可见性和实体生命周期；不得把区块卸载的移除原因当作列车销毁。

## 已尝试失败

`0.2.24` 只在旧存档格式迁移时隐藏旧记录，但当前格式中上次保存为 `LOADED（已加载）`的记录在重启后仍直接可见；同时车辆段列表仍读取全局列车。该方案不得再次使用。
