# BUG-071：第一次立即发车误报线路中断

- 类型：数据保存 / 读取问题、核心线路校验问题
- 状态：`0.2.39` 已修复代码，待游戏验收
- 影响版本：Minecraft（我的世界）`1.21.8`、`1.21.11`

## 1. 问题现象

进入游戏后第一次点击“立即发车”提示线路断轨；打开车站或道岔状态后再次点击即可正常发车。

## 2. 根本原因

旧道岔记录的 `switchEntryOrdinal`（道岔入口序号）可能为空。立即发车校验直接使用未补齐的记录，而打开道岔设置窗口会把方块的实际放置入口补写到 SavedData（全局存档数据），造成“必须先查看设备，第二次才成功”的假象。

## 3. 修改文件

- 两版 `SwitchEntryStateSynchronizer.java`
- 两版 `DepotNetworking.java`
- 两版 `DeviceSettingsNetworking.java`
- 两版 `ImmediateDispatchSwitchSyncContractTest.java`
- 两版 `RailwayManagerScreen.java` 与八种语言文件

## 4. 具体修复方式

立即发车完整校验前，统一同步线路上全部旧道岔的入口记录；设备设置窗口改用同一个同步服务，不再各自维护不同逻辑。选中线路时，在“线路”标题下显示“正在修改：线路名称”，并为该行预留布局空间。

## 5. 验证

- `1.21.8`、`1.21.11` 定向编译与回归测试通过。
- `ImmediateDispatchSwitchSyncContractTest` 保证同步发生在立即发车验证之前，且设置窗口复用同一服务。
- 仍需在游戏中重启存档后直接点击一次“立即发车”验收。

## 6. 下次应避免

线路校验不得依赖玩家先打开任何设备设置窗口。旧数据补齐必须在服务端校验入口统一完成，且只填补无效值，不覆盖有效的玩家设置。
