# BUG-046：双车辆段覆盖道岔入口，手动编组方向未保存

## 1. 问题类型

核心逻辑问题 / 数据保存问题 / 线路验证问题

## 2. 问题现象

实际信号铁轨完整，线路仍提示“`1w` 与 `站点1` 之间的轨道不完整”。同一世界中，手动连接的客车、货车和特快列车都容易停在道岔前。火车头与车厢连接后没有按连接前的相对位置稳定确定 W 的正方向。

## 3. 根本原因

旧 `SwitchEntryDirectionService（道岔入口方向服务）`每 20 游戏刻扫描道岔四个分支，并把 64 格内最近的任意车辆段当作固定入口。用户布局中同一道岔同时连接发车车辆段与回收车辆段，回收车辆段可能覆盖发车侧入口；线路选择的“直行”因此被换算到错误的绝对出口，造成完整轨道误报断轨。

`TrainLink（列车连接数据）`没有保存编组正方向。整列逻辑控制器在静止或重建运行游标后只能使用火车头模型朝向猜测方向；道岔前又只按同一高度检查相邻铁轨，进一步造成所有车型共用的停车问题。货车类型不是根因。

## 4. 修改文件

- `route/SwitchEntryDirectionRules.java`、`route/SwitchRailRouting.java`、`route/WorldLineValidator.java`
- 删除 `route/SwitchEntryDirectionService.java`并移除服务器周期注册
- `data/RailwayDevice.java`、`data/RailwaySavedData.java`
- `network/DeviceSettingsNetworking.java`、`client/DeviceSettingsScreen.java`
- `train/TrainLink.java`、`train/FormationDirection.java`、`train/RailMotionCursor.java`
- `train/TrainFormationService.java`、`train/TrainControllerManager.java`、`train/RailHeightOffsets.java`
- `depot/DepotDispatchService.java`
- 八个语言文件、版本文档及相关回归测试

## 5. 具体修复方式

道岔固定入口改为独立的 `switchEntryOrdinal（道岔入口序号）`存档字段。新放置道岔保存玩家放置时确定的入口；旧存档没有字段时使用方块已有的 `placement_entry（放置入口）`迁移。设置窗口增加北、东、南、西四个入口按钮。线路验证、方块高亮、红石切换、手动列车和自动列车统一读取该字段，不再扫描或比较附近车辆段距离。

连接火车头与车厢前，使用两者尚未吸附时的位置向量确定“从车厢指向火车头”的正方向，并写入编组内每节车辆的 `FormationForwardOrdinal（编组正方向序号）`。车厢与车厢连接保持无方向；首次连接火车头时才确定。运行后由铁轨运行游标持续提供真实前后方向，S 倒车读取反向。道岔出口的铁轨存在性检查同时检查同层、下一层和上一层。

## 6. 如何验证已经修好

- 新增测试先因缺少持久入口、编组方向和高低轨道候选而编译失败，形成确定的失败反馈。
- `SwitchEntryDirectionRulesTest`覆盖保存入口优先、旧世界回退和非法方向拒绝。
- `FormationDirectionTest`覆盖四向位置推导与重合位置不臆造方向。
- `TrainLinkStateTest`覆盖编组方向状态。
- `RailHeightOffsetsTest`覆盖同层、下层、上层顺序。
- `SwitchEntryPersistenceContractTest`确认服务器不再注册最近车辆段周期覆盖，并确认入口进入存档与设置数据包。
- 最终仍需在用户当前双车辆段世界中完成游戏内验收。

## 7. 下次遇到类似问题应避免什么

固定业务状态不得由附近世界结构周期性重算，尤其不能用“最近任意设备”代替线路指定的职责。手动列车方向不得在每次静止时从模型朝向重新猜测；连接时已经确定的信息必须进入持久数据。铁轨连通判断必须共用支持高度差的查找规则。

## 已尝试失败

- 每秒扫描并选择最近车辆段作为道岔入口：已失败，禁止恢复。
- 静止列车使用车头模型朝向代替连接位置方向：已失败，禁止恢复。
- 道岔出口只检查同一 Y 坐标铁轨：已失败，禁止恢复。
