# BUG-039：Ctrl+右键车辆段设置入口被其他交互回调截断

## 问题类型

客户端交互问题 / Fabric Event（Fabric 事件）顺序问题

## 问题现象

在实际 26.2 整合包中，按住 `Ctrl（控制键）`右击车辆段没有打开编组设置；普通右击库存仍可用。

## 根本原因

车辆段的通用 `UseBlockCallback（使用方块回调）`在主模组初始化时注册，但旧的 Ctrl 专用回调
在所有主初始化完成后的客户端初始化阶段才追加。整合包中的其他交互模组可以在两个回调之间注册，
并在返回非 `PASS（继续）`时终止事件链，导致 Ctrl 专用回调没有执行机会。

控制键读取接口本身经过当前 26.2 映射 JAR 的 `javap`验证可用，并非按键码错误。

0.2.6 将判断移到最早注册的 Fabric 通用回调后，实际整合包复测仍然打不开，说明冲突发生在
Fabric 回调开始之前；仅调整 Fabric 回调内部顺序不能解决。

## 已尝试失败

- 在 `FabricTrainClient`末尾单独注册第二个 Ctrl 回调：编译通过，但实际整合包事件顺序不可靠。
- 0.2.6 让最早的通用 Fabric 回调委托客户端桥接器：自动测试通过，但实际整合包仍失败，已明确淘汰。
- 不能依赖服务端直接读取 Ctrl：原版右击方块数据包不携带控制键状态。

## 修改文件

- `src/main/java/cn/quit5700/fabrictrain/train/DepotSettingsGesture.java`
- `src/main/java/cn/quit5700/fabrictrain/train/DeviceInteractionService.java`
- `src/client/java/cn/quit5700/fabrictrain/FabricTrainClient.java`
- `src/client/java/cn/quit5700/fabrictrain/mixin/client/MinecraftUseItemMixin.java`
- `src/main/resources/fabric_train_simulator.client.mixins.json`
- `src/main/resources/fabric.mod.json`
- `src/test/java/cn/quit5700/fabrictrain/train/DepotSettingsGestureTest.java`

## 修复方式

保留不引用客户端类的交互桥接器，在 `Minecraft.startUseItem（Minecraft 开始使用物品）`方法入口
增加优先级 2000 的客户端 Mixin（混入）。命中车辆段且按住左右任一 Ctrl 时，先发送设置请求并
取消后续方块交互；未按 Ctrl 时完全放行，因此普通右击库存与上方铺轨不变。

## 验证

- 当前 Minecraft 26.2（我的世界 26.2）映射 JAR 确认 `InputConstants.isKeyDown(Window, int)`实际调用 GLFW 按键读取。
- 字节码检查确认 Mixin 目标为 `startUseItem`、优先级为 2000，并调用既有设置桥接器。
- 资源测试确认 `fabric.mod.json`声明客户端 Mixin 配置；最终仍需在实际整合包内验收一次 Ctrl+右键。
- 0.2.8 完整回归发现资源测试误把客户端源码路径写成 `src/main/java`；修正为真实的 `src/client/java`后测试通过。该问题只影响测试有效性，未改生产交互代码。

## 下次避免

实际整合包已证明 Fabric 回调入口仍可能太晚。需要抢占原版交互的客户端手势应在原生输入方法入口
处理，同时保持服务端距离和方块实体校验，不能只靠调整 Fabric 回调注册顺序。
