# BUG-054：设置器按钮失效且停车位置要求手动绑定

## 问题类型

客户端界面 / 输入事件 / 线路验证问题。

## 问题现象

1. 铁路线路设置器操作节点后，保存、关闭、翻页或方向按钮可能点击无效。
2. 界面显示“绑定停车轨道”，玩家必须退出界面再点击铁轨；该操作并非用户需要。
3. 手动绑定开始后，服务器会长期保存等待点击状态，下一次使用设置器可能被误当成绑定操作。

## 根本原因

1. 设置器自定义中栏拖动使用 `draggedDevice（拖动设备）`和 `draggedNode（拖动节点）`保存鼠标捕获；原版按钮先处理下一次点击时，旧捕获没有重置，随后的释放事件仍走旧拖动分支。
2. 手动绑定按钮关闭界面后，把玩家 UUID（通用唯一识别码）写入静态 `STOP_BINDINGS（停车绑定会话）`。除非玩家成功点击一格信号铁轨或服务器重置，否则会话不会结束。
3. 原自动迁移只按站点附近距离选择铁轨，遇到等距轨道就要求人工处理，没有利用已经扫描成功的实际线路轨迹。

## 具体修复方式

1. 每次新的鼠标按下事件先统一清除旧设备/节点拖动捕获，再交给原版控件处理；正常中栏点击随后重新建立本次捕获，释放时只处理当前操作。
2. 删除“绑定停车轨道”按钮、`BIND_STOP（绑定停车点）`网络操作和 `STOP_BINDINGS（停车绑定会话）`，设置器不再进入拦截下一次世界交互的隐藏状态。
3. 刷新线路时，对站点周围三维候选信号铁轨进行一次多目标路径搜索；成功轨迹按路径长度和站点距离选择。停车点随后只从这段已验证轨迹中选取并持久保存，验证、运行和卸货继续共用同一坐标。

## 已尝试失败

- 仅让绑定模式在点击错误方块时退出：仍保留一个用户不需要的模式，也不能解决按钮拖动捕获，未采用。
- 按站点附近欧氏距离直接选最近铁轨：可能选择相邻线路，已由“从验证成功轨迹中选择”取代。

## 如何验证

1. 打开设置器，反复交替拖动节点与点击保存、翻页、方向、关闭按钮；按钮必须始终响应。
2. 确认设置器没有“绑定停车轨道”，用设置器点击任意铁轨也不会进入绑定消息或拦截状态。
3. 在站点旁铺两条靠近线路，刷新目标线路；停车位置必须在目标线路上。改变轨道高度或路线后再次刷新，位置应自动更新。

## 下次遇到类似问题应避免什么

自定义拖放和原版按钮必须共享清晰的单次输入生命周期，任何新按下都应取消旧捕获。临时世界选择模式必须显式可取消且有超时；能够从已验证业务数据自动确定的坐标，不应要求玩家手动绑定。
