# BUG-064：登录后已有自动列车停止

## 1. 问题类型

数据保存 / 自动列车启动恢复

## 2. 问题现象

退出并重新进入存档后，原本正在运行的线路自动列车仍保留在原位置，但停止不动。

## 3. 根本原因

旧规则把服务器重启识别为统一回收时机。已加载自动列车进入 `tryStartupRecovery（启动恢复）`后先停止，再等待回收车辆段加载并接收整列；离线自动列车也被加入启动回收集合。因此车辆段区块未加载或库存不能接收时，原列车会长期停住。

## 4. 修改文件

- `TrainControllerManager.java`
- `OfflineTrainService.java`
- `StartupAutomaticResumeRules.java`
- `StartupAutomaticResumeRulesTest.java`

## 5. 修复方式

- 已加载线路自动列车在启动时重新验证线路、重建完整运行路径和运动游标，并按线路运行状态决定是否继续。
- 线路运行中且路径恢复成功时，从保存位置恢复自动运行。
- 线路暂停、维护、关闭或路径尚未恢复时保持停车，不错误执行启动回收。
- 离线自动列车在重启后继续保留离线状态，不再加入启动回收集合。
- 手动列车和正常到达回收车辆段的业务流程不变。

## 6. 验证

- 新增启动恢复规则测试，覆盖自动/手动、线路运行/暂停和路径成功/失败。
- 运行相关测试及完整 Gradle（构建系统）测试。
- 仍需在游戏中验证运行中保存、站点停靠时保存和长线路离线列车三种场景。

## 7. 构建过程记录

首次实现后 Java（爪哇）编译失败，原因是新增路径恢复代码漏导入 `TrackPoint（轨道点）`和 `LineLoopRules（环线规则）`。已补充精确导入。该失败方案不得通过复制全限定名或重写无关代码绕过。

## 8. 下次避免

服务器启动逻辑必须区分“恢复运行”和“业务回收”，不得再次把服务器重启本身当作自动列车回收条件。
