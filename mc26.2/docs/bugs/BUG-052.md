# BUG-052：永久道岔锁产生幽灵等待、历史列车残留且立即发车不刷新线路列车

## 类型

核心逻辑 / 数据保存 / 自动发车问题。

## 问题现象

1. 自动列车在道岔前长时间等待，即使占锁列车已经删除或不再经过该道岔。
2. 已删除的手动列车仍显示在车辆段“列车列表”。
3. 每次点击“立即发车”只增加列车，不能用最新线路替换该线路已有的自动列车。

## 根本原因

1. `0.2.19` 虽然分离了手动与自动选路，却继续使用跨游戏刻保存的道岔占用锁。部分异常退出路径没有释放锁，形成与真实实体无关的幽灵占用。
2. 列车身份记录没有存档格式迁移标记，也没有持久销毁标记。旧记录无法区分“未加载的真实列车”和“已经删除的历史列车”。
3. “立即发车”直接调用普通生成逻辑，没有把验证、生成替代列车和注销旧自动列车组成安全事务。

## 具体修复方式

1. 删除 `SwitchLockManager（道岔锁管理器）` 和持久通过状态。服务端每游戏刻从真实列车实体重新计算道岔 Realtime Traffic Right（实时通行权）：已经占用者优先，其次按距离和列车 UUID（通用唯一识别码）稳定排序。列车消失后下一刻自然失去通行权，不需要补偿性解锁。
2. 自动列车增加同轨前车安全停车距离。无权进入道岔或前方有真实列车时减速停车，并分别输出明确诊断原因。
3. 列车注册表增加 `TrainPresenceFormat（列车存在状态格式）` 与 `PendingTrainDeletions（待删除列车）`。旧记录先隐藏；真实实体加载会恢复原编号；明确删除的 UUID 不会被晚加载实体重新激活。
4. “立即发车”总是先清除旧运行时缓存并完整验证最新线路；随后先生成替代自动列车，成功后才静默注销同线路旧自动列车。验证或生成失败时不删除旧车。

## 已尝试失败

- `0.2.19` 的永久道岔占用锁：即使补充更多异常释放入口，仍可能遗漏删除、断轨、线路变化或未加载实体路径。已废弃并删除，不得恢复。
- 先删除旧自动列车再验证或生成新车：失败时会导致整条线路突然无车。未采用。

## 如何验证

1. 两列真实列车同时接近同一道岔，确认只有一列通过；删除先行列车后，后一列在下一游戏刻获得通行权。
2. 回收、脱轨或创造模式删除整列，确认列表、在轨数与运行状态清除；普通区块卸载不得注销列车。
3. 修改线路后点击“立即发车”，确认新自动列车使用最新路线，同线路旧自动列车静默消失，手动列车和其他线路不变。
4. 断轨、断电或库存不足时点击“立即发车”，确认显示具体原因且原自动列车仍保留。

## 已执行验证

- 实时通行权、停车距离、列车存档迁移和立即发车事务的定向自动测试通过。
- UTF-8 中文路径下完整 `clean build（干净构建）`通过：174 项测试，失败 0、错误 0、跳过 0。
- 八种语言各 239 个键，键集合一致；最终 JAR 内 78 个 JSON（JavaScript 对象表示法）文件全部解析成功，`fabric.mod.json` 版本为 `0.2.20`。
- 分发 JAR 与安装到游戏目录的 JAR SHA-256（安全散列算法 256 位）一致。
- 真实游戏内双列车争用、线路刷新和区块卸载/重新加载仍需玩家验收，未在没有实际运行游戏的情况下宣称通过。

## 下次遇到类似问题应避免什么

安全资源不得仅依赖各异常分支主动释放；能由当前真实世界状态重建的状态应按游戏刻重算。替换运行实体必须先验证并成功创建新实体，再清理旧实体。
