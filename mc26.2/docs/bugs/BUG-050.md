# BUG-050：自动道岔受手动方向阻塞且连续发车错误消耗库存

> 状态：`0.2.18` 中“自动列车临时改动现场道岔，尾车离开后恢复”的方案已经实际游戏证实失败。禁止重复使用；最终替代方案见 `BUG-051`。

## 类型

核心逻辑 / 自动线路运行 / 数据保存问题。

## 问题现象

1. 线路自动列车到达道岔时，如果线路要求方向与玩家保存的手动方向相同，可立即通过；方向不同时会在道岔前和道岔上长时间等待。
2. 点击车辆段“立即发车”后只产生一列，之后没有按发车间隔补充到“在轨列车”上限。
3. 创造模式第一次立即发车可以不消耗车辆物品，但后续定时发车仍尝试消耗库存；空库存时失败，而且窗口没有显示失败原因。

## 根本原因

1. 自动列车预设道岔时，旧代码把线路的左转/直行/右转选择套在道岔保存的固定入口上，再推导原版 `RailShape（铁轨形状）`。这不是列车当前缓存路径的实际进入边和离开边；同时只改物理形状，没有同步临时高亮状态，尾车离开后也没有恢复玩家的手动方向。
2. 自动调度虽然保留了“启用”状态，但周期入口仍把后续列车固定按生存库存规则生成。实际存档中的发车车辆段和相邻箱子均为空，因此第一次创造模式免库存成功，之后周期尝试立即失败，看起来像完全没有继续发车。
3. 周期失败结果没有持久保存和显示，用户无法区分达到上限、库存不足和线路错误。

## 修复方式

1. 自动列车直接读取 `Runtime Path Cache（运行时路径缓存）`中当前道岔前后的精确轨道坐标，生成本次真实 `RailShape（铁轨形状）`；不再由手动方向或旧固定入口推导自动路线。
2. 自动列车到达前同时切换物理形状和临时高亮；最后一节车厢离开并释放占用锁后，从持久设备数据恢复玩家保存的手动方向。
3. 把周期发车判定提取为可测试的 `AutomaticDispatchSchedule（自动发车计划）`，达到间隔且在轨自动列车低于上限时继续尝试。
4. 立即发车成功时记录启动玩家是否为创造模式。该自动任务的后续发车沿用此库存策略：创造模式不消耗，生存模式消耗；下一次成功的立即发车会更新策略。
5. 保存最近一次自动发车结果，并在车辆段设置窗口显示本地化状态。

## 已尝试失败

- 仅根据道岔保存的固定入口和线路“左转/直行/右转”计算自动列车物理形状：在列车实际来向不同或重复经过同一道岔时会选错出口，禁止再次采用。
- 只修改原版 `RailShape（铁轨形状）`而不处理临时高亮和尾车恢复：界面状态与实际路线不同，也会覆盖手动选择，禁止再次采用。
- 后续定时发车固定消耗库存且不记录失败结果：创造模式空库存表现为只发一列，禁止再次采用。

## 验证方式

- `AutomaticSwitchRouteContractTest`验证道岔窗口删除固定入口控件、自动列车读取缓存形状、同步临时方向并在尾车离开后恢复手动方向。
- `RailMotionCursorRouteShapeTest`验证普通道岔和线路中重复道岔的本次实际形状。
- `AutomaticDispatchScheduleTest`验证按间隔继续发车、达到上限停止和低于上限恢复条件。
- `AutomaticDispatchContinuationContractTest`验证创造模式库存策略、结果保存和状态显示接线。
- 线路、车辆段、道岔、存档相关的 66 项历史与新增回归测试通过；完整干净构建的 167 项测试通过，失败 0、错误 0、跳过 0。仍需在实际游戏中验收实体通过时间和真实容器扣除。

## 下次避免

自动线路已经拥有精确轨迹时，任何运动、道岔或校验逻辑都应优先读取该轨迹，不能再从手动设置反推路线。自动任务的权限或库存策略必须随任务持久保存，并且后台失败必须有可见状态，不能只观察是否生成实体。
