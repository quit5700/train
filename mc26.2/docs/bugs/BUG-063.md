# BUG-063：正式模型更新后旧资源测试失败

## 问题类型

Gradle 构建 / 资源回归测试

## 问题现象

正式写入已确认的信号铁轨和道岔纹理后，`InventoryPresentationResourcesTest` 与 `SwitchModelResourcesTest` 仍要求旧版立体物品变换、原版交叉铁轨叠加和钻石块高亮，导致 3 条测试失败。

## 根本原因

模型规格已经由旧版程序生成几何改为已确认的独立像素纹理，但资源回归测试没有与正式规格同步。

另外，首次批量 JSON（JavaScript 对象表示法）校验使用 Windows PowerShell 5.1 的 `ConvertFrom-Json`；项目旧方块状态包含空字符串属性名，触发 PowerShell 5.1 已知的不兼容行为。该方法标记为“已尝试失败”，不得再用于全量资源校验。

## 修改文件

- `src/test/java/cn/quit5700/fabrictrain/InventoryPresentationResourcesTest.java`
- `src/test/java/cn/quit5700/fabrictrain/SwitchModelResourcesTest.java`
- 信号铁轨、道岔和车辆段的正式模型及纹理资源

## 修复方式

- 测试改为验证新的平面物品纹理引用。
- 道岔测试验证井字底纹、左转/直行/右转三个模型，以及四个入口各三种状态均存在。
- 全量 JSON 校验改用显式 UTF-8（统一码）的 Python（蟒蛇语言）标准 JSON 解析器。

## 验证方法

运行 `gradlew.bat test build sourcesJar --no-daemon`，并检查普通 JAR 与 sources JAR 中包含新模型和纹理。

## 后续避免事项

- 正式替换已确认的资源规格时，同步更新只描述旧外观的回归测试，不得跳过或弱化资源存在性和状态完整性检查。
- Windows PowerShell 5.1 不再用于解析含空字符串属性名的全量 Minecraft（我的世界）方块状态 JSON。
