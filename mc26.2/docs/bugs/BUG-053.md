# BUG-053：到站继续挪动且前车离开后后车恢复过慢

## 问题类型

核心逻辑 / 自动线路运行 / 列车生命周期问题。

## 问题现象

1. 火车头已经到达站点绑定的停车轨道，但仍向前或向后挪动数格才停住。
2. 前方列车已经开始行驶，后车仍要等待它离开完整安全距离才开始移动。
3. 前方整列被摧毁或回收后，列车列表和后车等待状态不能在同一控制周期更新。

## 根本原因

1. 到站代码只把实体速度设为零并加入 `PAUSED（停靠）`表，没有清零整列逻辑控制器的 `LogicalSpeedState（逻辑速度状态）`，随后本刻的路径游标仍继续前进。
2. 跟车判断只有“完全畅通/完全阻塞”两种结果。即使前车已同向前进，只要距离仍小于静态停车距离，后车就继续保持零速。
3. 销毁通知先进入待处理表，原控制循环到所有列车处理结束后才注销身份；后车在此之前已经完成本刻阻挡判断。

## 具体修复方式

1. 车头首次到达线路节点保存的精确 `StopTrack（停车轨道）`时，吸附到轨道方块中心，并同步清零实体速度和逻辑速度；路径游标定位到同一格，防止发车时从越过位置继续。
2. 跟车判断改为每游戏刻产生 `FollowingTrainDecision（跟车决策）`：静止或对向前车要求停车；同向移动前车允许后车立即启动，但后车目标速度不能超过前车当前逻辑速度。
3. 每个世界建立真实列车集合后、计算通行权和后车运动前，先注销已经没有任何实体的待销毁列车。列表、在轨计数和运行缓存因此先于后车判断更新。

## 已尝试失败

- 只给实体调用 `setDeltaMovement(Vec3.ZERO)`：整列逻辑控制器仍保存非零速度，下一步又会推进路径，禁止重复采用。
- 前车只要仍在安全距离内就让后车保持零速：安全但造成明显的排队迟滞，已由同向速度限制取代。

## 如何验证

1. 以不同速度进入车站，车头应始终停在绑定停车轨道中心，列车不前后抖动，发车时从该点继续。
2. 两列自动列车在同一轨道排队；前车离站后，后车下一游戏刻开始移动，同时保持安全间距。
3. 回收或摧毁前方整列，立即查看列车列表和在轨数，再观察后车恢复；普通区块卸载不能被误判为销毁。

- 精确停车坐标、逻辑速度硬停止、路径游标同步、同向跟车速度限制和销毁处理顺序的定向自动测试通过。
- UTF-8 中文路径下完整 `clean build（干净构建）`通过：179 项测试，失败 0、错误 0、跳过 0。
- 八种语言各 239 个键且键集合一致；最终 JAR 内 78 个 JSON（JavaScript 对象表示法）全部解析成功，模组版本为 `0.2.21`。
- 分发 JAR 与安装到游戏目录的 JAR SHA-256（安全散列算法 256 位）一致。
- 真实游戏内高速进站、双列车排队和销毁前车后的下一刻恢复仍待玩家验收，未在没有运行游戏的情况下宣称通过。

## 下次遇到类似问题应避免什么

整列逻辑控制器接管车辆后，任何停车功能都必须同时更新实体、逻辑速度、路径游标和跟随轨迹，不能只修改原版矿车速度。队列控制要区分静止障碍与同向移动目标，并且销毁生命周期必须先于交通决策结算。
