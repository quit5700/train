# BUG-002：存档测试运行时缺少 Minecraft 类

## 问题现象

`RailwaySavedDataTest`（铁路存档测试）编译成功，但运行时报 `NoClassDefFoundError: SavedData`。

## 根本原因

为兼容中文路径而自定义的 JUnit（单元测试）类路径只加入了 `testRuntimeClasspath`（测试运行类路径），没有包含 Loom（Fabric 构建插件）提供的 Minecraft 运行类路径。此前测试只使用纯 Java（爪哇）类，因此没有暴露问题。

## 修改文件

- `build.gradle`
- `src/test/java/cn/quit5700/fabrictrain/data/RailwaySavedDataTest.java`

## 已尝试失败

仅把 Gradle（构建工具）的 `runtimeClasspath` 加入测试类路径仍然找不到 `SavedData`，因为 Loom 的重映射游戏 JAR 不在该普通配置中。后续不得重复只追加该配置。

## 修复方式

在保留 ASCII（纯英文）临时测试输出的同时，显式加入 Loom 缓存中与 `minecraft_version` 对应的 `minecraft-merged-deobf`（重映射游戏 JAR），并继续包含测试和主运行依赖。

## 验证方式

运行完整干净构建，并确认铁路存档的编码、解码和编号不复用测试通过。

已单独运行 `RailwaySavedDataTest`（铁路存档测试），测试通过；后续完整构建继续覆盖该测试。

## 下次应避免

中文路径兼容方案不能只验证纯 Java 测试；新增依赖 Minecraft 类的测试后必须同步检查运行类路径。
