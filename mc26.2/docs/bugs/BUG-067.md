# BUG-067：逐节删除后列车列表残留，连接与拆分缺少成员登记

- 类型：数据保存 / 实体生命周期 / 编组连接 / 客户端与服务端
- 状态：`0.2.33` 已修复代码，待游戏内验收

## 1. 问题现象

列车注册表只知道列车 UUID（唯一标识符）和存在状态，不知道具体包含哪些车头、客车和货车。玩家逐节删除、连接、从中间断开或离线恢复后，列表可能残留空列车，也不能稳定判断何时清理整列资源。

## 2. 根本原因

旧实现只上报“某列车有实体被销毁”，再扫描当前已加载实体判断整列是否消失。该方法无法区分具体成员，也无法让连接、拆分、区块卸载和离线实体使用同一个权威数据源。车辆段列表还只读取当前线路自动列车，不符合后来确认的手动列车显示规则。

## 4. 具体修复方式

每列车持久保存来源车辆段号和按顺序排列的成员实体 UUID、车型及内部序号；列车号继续使用只增不回收的全局计数器，读取旧存档时发现重复号码会自动分配新号码。车辆实体内部保存 `#车辆段号.列车号.车辆序号` 地址，但不向玩家显示。

破坏一节车辆时只移除对应成员；总车辆数为零后调用统一注销入口。正常区块卸载不减少成员。连接时有车头一侧继承原列车号并拒绝双车头；从中间断开时车头段继承原号，另一段获得新号并重新排序。离线列车重新实体化时整体替换成员，避免旧实体 UUID 残留。

车辆段列表显示全局有效手动列车和当前线路自动列车，每秒只在数据变化时刷新。右侧删除按钮会静默删除实体及货物，并清理列表、在轨计数、道岔权、运行缓存和离线状态；未加载实体通过待删除标记阻止以后复活。

## 6. 下次应避免

不得再用“当前已加载实体扫描”作为列车成员的唯一事实来源；不得只存车辆数量而不存成员 UUID；连接、拆分、回收和删除不得分别维护互不一致的列表状态。

## 已尝试失败

- `0.2.24` 只隐藏旧记录，没有解决当前实体成员同步。
- `0.2.25` 只按线路过滤自动列车，规避了手动列车残留显示，但没有修复成员生命周期。
- Minecraft 26.2 不公开旧版客户端 `screen（当前窗口）`字段；本次首次编译已发现并放弃该方案，改为列车列表窗口自身维护短期活动实例。
