# 自动列车重进重叠

- 归类：存档恢复、离线状态转实体和轨道占位。
- 现象：26.3 的 f4 线路上 114、115 两列车车头仅差 0.135 格，两套九节编组几乎完全重叠。
- 根因：同一刻恢复多列实体时只检查区块是否加载，未检查其他车或同刻刚恢复的完整编组。车头与对方车厢交错后，跟车保护可能互相限速或停车。
- 文件：十版 OfflineTrainService.java 和 TrainControllerManager.java。其余八版同时同步已交付的进档供电后备检查。专项在 OverlapRestartProbe.java。
- 修复：按线路位置优先恢复前车，检查所有车厢占位并预留同刻已恢复编组。后车在离线记录中等待空位，等待时间不累计为位移，保留原列车编号、车厢和货物。
- 验证：旧版以原存档副本复现重叠。26.3 新版在两次实际退出重进中均未重叠，原两列车都跨区块，逐车核对车厢顺序和真实保存的测试货物。十版完整自动检查4583项通过。
- 已尝试失败：单列车退出重进无法发现重叠。初版双列车探针观察范围过短，列车驶出后仅数实体会误判货物丢失。扩大临时观察范围后逐节对照实际货物。只加占位检查时，第二次重启仍有后车车头追上前车静止车尾的情况。恢复时用整列车位置初始化跟随轨迹后重测。
- 防回归：不能只比较车头或等实体索引下一刻更新。测试两列真实编组跨区块，并验证再次退出重进仍保持分离。
