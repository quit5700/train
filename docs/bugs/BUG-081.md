# BUG-081：第二点修改状态与右键优先级

当前根：Fabric模拟火车模组。分类：界面会话／交互状态。发现于本次新交互的审查和针对性自动测试，不是引用其他项目BUG。

现象风险：从列表点修改后客户端关闭列表，服务器若仍保留列表会话，随后第二次左键保存时的共享广播会把列表重新打开。普通Item.useOn还晚于箱子或车辆的原生交互，工具右键可能被打开箱子或乘坐抢走。

根因：临时选区会话与已打开的列表会话未分开结束；仅修改物品右键函数无法覆盖原生方块/实体的交互优先级。

文件：十版AccessNetwork.java、StationAccess.java、RangeStateTest.java。

修复：beginSecondPointEdit保留第一点、维度和范围身份，同时移除列表会话；共享广播只更新仍真实打开的有效列表。用方块和实体使用前回调让手持设置器优先打开列表，空中使用仍由物品负责；不持有设置器返回PASS（继续原生交互）。

验证：secondPointEditReleasesListSessionAndKeepsAnchor直接检查生产代码的状态迁移，证明保存广播不会再依据旧列表会话自动打开列表，同时第一点仍保持原值；所有版本编译、完整原回归与服务器保存重载按最终报告核对。真实鼠标输入仍待用户实测，不把状态测试称作实机点击验收。

已尝试失败：只关闭客户端界面而不清服务端列表会话；仅在物品useOn中定义右键优先级。禁止以后原样采用。不得为了修此状态问题移除共享广播或禁止修改范围。
