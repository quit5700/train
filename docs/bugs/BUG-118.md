# BUG-118 · 1.21.4 更换车辆段后已匹配货物仍不进货

类型：库存状态与编组规则恢复。修复版本：0.2.42-test40（测试版）。

现象：更换出发车辆段后，临时箱群中的钻石等已被分类选中的物品没有再进入货场，对应卸货站没有收到货物。

真实复现：“测试宝箱”原存档只复制至H盘独立实例。货场13当前线路为1，新出发车辆段11的PCCC编组、三个规则和卸货站5/1/7都正确。实际inputs访问7个连通的万能宝箱临时保管箱成员；64钻石与钻石工具、金制工具、红石类都有heldReturns保留记录。旧包通过真实DepotNetworking保存切换车辆段3→11，实际生成列车跑完全线并回收，但货场、车厢及三个目标站均没有收到这些物品。

根因：隐藏车厢库存退还来源箱后，heldReturns阻止它们立刻被重新取入。旧实现只在来源库存减少/清空时缩小保留量，没有在当前有效车厢规则重新接受这些物品时解除保留。因此只要箱子保留原物品，即使线路、编组和规则已经重新匹配，也会永久跳过。

修改文件：FreightYard.java新增按实际来源和有效车厢规则解除保留的方法；FreightYardService.java在每次读取输入容器前调用。仅解除该来源、且被当前有效车厢页选中的物品。隐藏页、不匹配物品和其他来源保留保护，不清空所有记录。FreightReturnedStockTest.java新增3项回归：恢复匹配、隐藏规则/未选物品保护、保存重载及来源隔离。

验证：355项完整自动检查零失败。原存档副本使用实际安装的万能宝箱运行包、真实玩家网络保存动作、真实列车及正常游戏刻，完成新旧包对照。新包8项流程检查通过：旧段保存、新段保存、箱群到货场、货场到真实货车、钻石卸到jin、金工具卸到站点、红石卸到yuan、终点车辆段回收。64钻石及9件钻石装备工具到jin，4件金工具到站点，红石类320件到yuan，共有规则的64铁矿石按22/21/21分配。19种461件物品逐项核对全部守恒，没有把物品预填入车厢或直接调用卸货函数代替列车到站。

排除项：线路/车辆段绑定并未丢失；箱群六面遍历工作正常，不重复修改BUG-098已修实现；卸货目标继承和到站卸货代码正常，本次未改。其余生产类、所有界面、全部模型材质和资源逐字比较一致。未改用户存档，未安装诊断模组到用户mods，只更新1.21.4。

应避免：不能把全部“退回物品保护”永久当作黑名单，也不能为了恢复取货直接清空所有保护导致退货/进货循环。必须用真实临时箱群和整条线路验证，同时逐项核对物品去向与守恒。

开发验证备注：PowerShell中显式声明为XML类型的变量不可复用于JSON对象读取；本次结果读取遇到该类型约束后改用独立JSON变量，正式运行包不受影响。
