# BUG-104 · 26.1.2 在途自动货车卡在远端

- 分类：跨区块调度、线路编辑后的状态隔离、运行检查点恢复。
- 现象：「测试宝箱」的两列五节自动货车在 Z=213 和 Z=218 附近停住。前方轨道已加载，发电机区块未加载。旧包进档后持续 500 多刻未前进。
- 根因：车辆持有已验证的 523 格轨迹，但后续线路编辑删除了一个道岔节点。供电逻辑把旧发车计划与当前线路签名绑定，导致在途车远端供电判定失败；后台推进也使用新线路的节点索引。首次恢复实体时从方块坐标反推游标，经过方块边界的后车在首刻多移动了约 0.405 格，引发重叠。
- 修改文件：`offline/TrainDeparture.java`、`offline/InfrastructureData.java`、`offline/InfrastructureService.java`、`train/OfflineTrainSavedData.java`、`train/OfflineTrainService.java`、`train/TrainControllerManager.java`、`train/RailMotionCursor.java`。每列自动列车保存独立的发车线路和发电机记录。旧存档只从同车辆段且完整轨迹相同的已验证计划补录。发车校验沿用现有线路规则。实体恢复沿用已保存的路线索引和段内进度。
- 已尝试失败：仅恢复在途供电和节点后，两列车虽然到终点，但在恢复时发生重叠。不能以到达终点作为唯一通过条件。
- 验证：原存档副本以真实登录点对照旧包和最终运行包，核对两列车真实出现、驶离更新范围、在未加载终点回收全部车辆和物品以及无重叠。独立服务器从实际车辆段发车，测试真实卸载、未加载站点卸货、起点卸载后继续发车及重启后回收。
- 防回归：对比在途车的发车签名和编辑后的线路签名。测试轨道中心之间的检查点，并对同一真实运行过程逐刻检查整列车边界框。
