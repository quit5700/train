# BUG-119 · 1.21.4 列表残留与中途停车（已验证）

类型：区块生命周期、供电缓存、保存记录一致性。当前项目根目录为Fabric模拟火车模组。版本0.2.42-test41。

现象：列表四行而上限2，乘坐第一列后第二列在后续线路不动；人工破坏车辆后有残余车厢。用户要求已有4列不得直接删除，回收后低于2才补车。

根因与证据：现场只读采样35、36为已retired、无Owned和活动映射的列表残留，真实活动数曾为2。45在采样时车头已被人工移除，不能把该残余编组当作完整列车复现。用户删除重发后48、49曾完全重叠。真实保存副本旧包中49停在z260.5，running=true、following无阻挡、ticking=true但powered=false；已加载轨道重新可读后供电遍历没有扩展旧截断缓存。新版越过此点并到终点正常回收。

修改文件：1.21.4的power/RailPowerService.java采用本项目已验证的区块可读前沿重建方法；offline/InfrastructureService.java在回收事务及启动时同步关闭已回收且无后台所有权的记录。共同库存及授权修复另见BUG-120。其余九版只同步主页面控件清理与库存授权，不覆盖已验收的各版供电实现。

修复方式：跟踪不可读边界，只有边界实际可读时标脏并重新扫描，不强制加载区块；回收同一编号幂等，不重复归还车辆或货物。旧已回收且无后台所有权的记录移出列表。保留实际在轨编组及库存，不通过重置玩家线路掩盖问题。

验证：最终包358项单元回归通过；原“测试宝箱”副本1200刻实际乘坐49越过停车点，48、49均回收，自动补至2；6项轨迹断言通过。独立真实流程由4列保存降上限2，不删旧车，低于2才补车，6列最终各回收一次，7项通过。重载保留真实编组／货物且清除两条已回收幽灵清单，4项通过。加上十版共用模式、首次缺货补货及界面检查，1.21.4共39项实机检查。原存档未修改。

已尝试失败：只读代理直接调用私有嵌套record访问器产生IllegalAccessException，改用独立诊断类及setAccessible；Gson默认不能保存Infinity导致观察提前结束，改用非有限遥测值字符串与独立错误文件；不能把未到终点日志当通过。界面测试曾打开暂停页面后等待服务端指令，造成测试自身停住，改在客户端核对后关闭页面再继续。均未通过修改游戏业务绕过。

避免重复：列表、活动计数、后台Owned和retired必须联合核对；必须用自然加载范围变化及真实乘坐流程复现停车，不能只手填离线状态；必须比较回收数量及真实编组，不把四行列表直接判为调度超发。已被玩家拆除车头的残余编组不属于完整列车的到站回收测试，本次不声称补回玩家已销毁的物品。

证据：H:/CodexWork/q5-count-stall/原档乘坐回收最终核验.json、ghost-reload-final41.log、上限四降二实测及每版验证日志。失败尝试及最终证据随交接归档保留。
