# BUG-109 · 1.21.8 临时箱卸货与编辑线路后的在途恢复

- 类型：可选模组联动、离线库存和线路生命周期。
- 临时箱：站点已加载时使用真实容器正常写入。旧版在离线容量判断中只承认原版箱，真实自动车经过未加载站点后仍携带 64 件货物。只为相邻的 `universal_chest:buffer` 启用离线空槽容量，沿用已有投递账本和重新加载时的真实容器校验。
- 在途车：真实存档第 12、13 列的完整轨迹和发车计划一致，后续编辑去掉站点 1，当前线路成为待校验。旧版既挡住离线推进，又将旧计划电源判为无效。按本项目 BUG-104 已验证的做法，让在途车持有原发车节点和电源记录，从准确的进度恢复实体。第一次移植后，两列在恢复实体时仍停住。发电机和终点是两个加载区，中间区块不可读取。现只在起点实际有电、当前电源传播被未加载轨道截断、可读取的路径仍是信号铁轨或道岔时，继续使用已验证的供电。已发车后的路线独立，新车仍执行当前线路校验。
- 修改：`offline/InfrastructureService.java`、`offline/InfrastructureData.java`、`offline/TrainDeparture.java`、`train/OfflineTrainSavedData.java`、`train/OfflineTrainService.java`、`train/TrainControllerManager.java`、`train/RailMotionCursor.java`。
- 验证：原登录点加载两列实际存档车辆，核对旧版长期停留以及新版越过 yuan、回收车辆段库存增加和无重叠。真实万能宝箱运行包验证实际转移、后台到站、服务器重启与库存守恒。没有把货场的取货代码用于站点写入。
- 防回归：不要将当前线路的待校验状态套到已发车辆；不以已加载容器测试代替实际卸载和保存重载。
