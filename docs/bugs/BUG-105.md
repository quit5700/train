# BUG-105 · 26.1.2 供电误判与定时发车

- 分类：线路供电缓存、区块加载时序、主动发车校验。
- 现象：在「测试宝箱」远程打开车辆段，已验证线路和有效燃料存在，保存却提示车辆段上方未检测到供电。从车辆段附近进档，两列已发货车短暂推进后停住并持续占用两个自动发车名额。
- 根因：远程线路校验会临时读取发电机区块，方块实体可读取却不会执行更新。旧供电遍历只使用已更新的发电机登记，结果在可读取时忽略离线记录，在未登记时又无法计算真实供电。分段缓存也没有利用已验证的离线线路供电。另有 BUG-102 同类的自然加载缺口，供电第一次遍历先于远端区块可读，后续没有重算。
- 修改文件：`power/PowerSectionCache.java`、`power/RailPowerService.java`、`route/WorldLineValidator.java`、`depot/DepotDispatchService.java`。主动发车用有效燃料及真实接线补充读取到的发电机；被动读取不可用时检查已验证供电记录；只跟踪供电遍历实际遇到的不可读区块，区块可读后触发合并重算。线路、燃料和实体运行规则继续检查。
- 已排除：仅修正分段未知状态仍会在车辆段接入轨道返回未供电；从正常已加载的车辆段点击保存成功，不能覆盖远程失败；强制加载、手动点重置及手动刷新缓存会掩盖定时调度卡住，只在诊断对照组使用一次手动刷新。
- 验证：运行旧版与最终运行包，真实客户端发送远程保存请求，核对操作结果及新列车，断开发电机旁的红石接线确认真实断电仍拒绝。真实存档冷启动，无按键操作和手动刷新，观察旧车恢复、离开加载范围及自动补发。保留完整自动检查。
- 防回归：区分区块不可读与明确断电；跟踪两个在轨编号是否更新，不能只检查数量或车辆段上方一格。
