# BUG-075：运行中模组包占用导致替换失败

分类：安装文件操作／客户端进程。当前项目根目录为Fabric模拟火车模组Git（版本管理）仓库。

## 现象、原因与处理

用户授权替换当前1.20.1实例。完成旧包和全部存档备份、压缩包完整性检查及H盘副本摘要校验后，旧0.2.40运行包重命名失败，Windows返回WinError 32（文件被其他进程占用）。游戏仍持有旧JAR（Java归档）文件；运行中换包不是可靠方案，已尝试失败。安装中止并清理暂存包，未删除旧包，也未同时留下两个可加载的列车模组。

用户随后明确授权“强制结束”。核对进程24040启动目录后，只结束该1.20.1游戏进程，保留启动器。进程退出后复用已经校验的备份，重新核验其中旧包与磁盘旧包一致，再禁用旧包、安装0.2.41-test1。没有重新生成或改动模组功能。

修改文件为tools/install-trail-fix.py（安装工具），增加经校验备份复用、暂存字节验证、替换失败回滚、加载包元数据去重及安装报告。模组源码及运行包内容未因本次安装修改。旧JAR保留为.disabled_时间戳（已禁用）后缀。

## 实际验证

当前实例mods（模组目录）中可加载的fabric_train_simulator（列车模组）只有0.2.41-test1。安装包SHA-256（摘要）为50f60e51893b8dec627d9df65559a421a0e5f52340f99c581166111eae843c7a，与构建验证结果一致。安装前备份173195066字节，旧包及所有9个存档均保留；排除session.lock（运行锁），压缩包完整性通过，H盘副本字节摘要一致。

备份制作时游戏尚在运行，因此属于磁盘快照，不代表保存了内存中尚未落盘的进度。用户授权强制结束后，没有声称已执行正常保存。实际游戏需重新启动并测试；安装成功不等于正式版确认。

报告见docs/当前实例安装记录.json；备份和报告同时归档在本对话H盘Java轨迹修复_0.2.41-test1目录。

## 下次避免

先确认目标实例与进程身份，停止游戏后再换包。文件占用时不得删除、强制覆盖或留下多个相同模组标识的运行包。强制结束必须有用户明确授权；复用备份前要验证完整性和对应旧包，不以文件存在代替成功备份。

1.20.4-Fabric-mtr已安装0.2.41-test1，包内元数据及SHA-256校验通过，旧0.2.40已禁用保留。按用户本次要求不备份存档，只备份旧模组包及日志。安装记录为当前实例安装记录_mc1.20.4.json。取消的临时存档备份因删除命令被策略拦截，改用保留并标记.cancelled后缀的方式处理，不作为有效备份。1.20.1用户反馈正常，1.20.4待实测；两版仍为测试版。
