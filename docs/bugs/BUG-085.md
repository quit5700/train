# BUG-085：十版手动模式、车辆段列表归属与道岔四向连接

项目根目录：`C:/Users/quit5700/Documents/mc虚拟线路模组/Fabric模拟火车模组`。范围：本轮明确授权的十个版本，交付0.2.42-test5。用户还明确要求全部完成后一次性关机；先完成所有验证、安装和交接，再关机。

## 需求及原问题

1. 原手动列车只播放到站广播、不停车，是0.2.11起的旧规则。本轮用户明确变更：车辆段界面手动生成与自动生成之间加停站/自由两个互斥选项，无默认，不选不能生成手动车辆；自动按钮不受影响。新生成手动车辆保持静止。停站模式每站停，由玩家重新按W发车，不套用自动停靠倒计时；自由模式保持原玩法。
2. 原列表按当前选中线路筛选，旧线路自动车和未绑定线路时的手动车辆会被隐藏。列车已有永久生成车辆段归属，应该按该归属查询和删除，而不是改用当前线路。只列仍存在且有编组成员的列车；所属线路已删除时保留编号提示，不能越权删除其他车辆段的车。
3. 原寻路将道岔当成其可见RailShape（轨道形状）的两个邻接点。接入图应检查东、西、南、北四个物理端口；车辆段本身位于道岔下方时也要检查全部分支。真正行车时，手动遵守可见方向，自动遵守线路节点和真实驶入方向，不能把四向连通当成四向同时发车。

## 修改范围

十版独立源码：`versions/0.2.42-test5/mc<游戏版本>`，不覆盖test2/test3/test4。共用逻辑分别修改`ManualStationControl`、`TrainLink`、`TrainControllerManager`、`DepotNetworking`、`RailwaySavedData`、`DepotDirectionRules`、`WorldLineValidator`、`DepotSettingsScreen`、`TrainListScreen`和八语言资源。

`ManualStationControl`保存是否启用及是否正在候站，按键状态是瞬时状态；旧存档和手放车辆默认保持自由玩法。车辆段新生成必须显式选择。服务端拒绝未选择的手动请求，不能只靠客户端按钮禁用。生成模式写入编组成员的TrainLink（列车连接数据）并随实体保存。旧网络构造调用保留编译兼容，但无模式的手动请求不会绕过校验。

停车时始终包含车头自身，不能依赖当前实体枚举已返回车头。停站模式以不大于四分之一格的子步检查经过车站，避免高速一刻跨过车站；只有这一模式增加检查，不改变自动列车和自由模式运动。停车会归零逻辑速度、对齐站台停车点、取消延迟恢复并驻停整列。

按键边界已单独复现：若到站前已松开W，原候选要求再松开一次才离站；现记住到站前真实按键状态，首次新按W即可离站。若一直按住W则不能冲站，必须释放再按；重载候站时同样不能用持续按住的W绕过。红绿结果保存在本目录evidence/BUG-085/到站前已松W_修复前.txt及修复后.txt。

列表与删除共同使用`presentTrainsFromDepot`，保留原线路查询函数供其他功能使用。原`DepotTrainListContractTest`中“必须选择线路”“按线路筛选”的两条断言已按用户明确变更改为车辆段归属；其余请求、刷新、删除、返回及权限断言保留，并增加真正的数据归属测试，不以删测试通过。

道岔邻居图与发车候选分离：普通轨道仍按真实形状，只有道岔检查四侧；发车选择唯一最短可达分支，等长或无路继续拒绝，保留原安全规则。先前只在26.3修复的自动真实驶入方向、手动不依赖自动线路、清晰范围字体、具体节点报错及顶部名称显示，同步到十版；平台接口差异记录在BUG-086。

## 已尝试失败与防重复

- 仅在每刻开始检查当前方块会漏掉高速跨格经过的车站，最终使用子步检测。
- 未记录到站前是否已松W，导致玩家按两次才能离站；已有独立复现与状态机回归，不得退回单纯固定“先松后按”的无上下文状态。
- 实体枚举暂时不包含车头时，候选只设置了等待状态却未停车；最终始终将车头纳入编组停止。
- 不能靠清空线路选择来修复车辆列表，也不能把本车辆段的删除权限放宽到世界所有列车。
- 发车起点若为道岔，不能仍只取getFirst/getLast两个端口；新增四分支选择与起点侧向实际服务端检查。

## 验证

最终专项每版24项，新增真实网络模式编码往返、远端车辆段生成完整三车编组、直接给每个生成实体设置模式和保存验证。新生成实体未必已被世界枚举返回，因此`DepotDispatchService.DispatchOutcome`保留不可变的本次生成实体列表，`configureManualMode`直接使用该列表，不依赖区块是否在实体刻更新范围。涉及文件增加`DepotDispatchService`。

弯后同一刻停车曾因提前返回而遗漏本刻朝向更新，已先记录失败结果`转弯后停站朝向_修复前.json`；现在停车返回前同步轨道姿态和编组前向，与正常运动一致，不增加旋转补偿。

每版完整单元测试、原轨迹清理等历史回归、独立服务器功能与保存重载检查；每版再用`tools/probe_release5.py`在临时世界执行四向连接、两种侧向接入、真实实体到站停止、自由模式不停车、模式/候站状态NBT（命名二进制标签）保存重载、持续W与重新W、高速跨站和旧线路车辆归属检查。结果分别记录`evidence/BUG-085/专项-<版本>.json`，必须和最终源码指纹一致。
