# BUG-073：1.20.1／1.20.4轨迹清理死循环

项目根目录：当前Fabric模拟火车模组Git（版本管理）仓库。分类：服务端核心逻辑／集合操作／性能问题。

## 现象与原因

用户反馈1.20.1版0.2.40轨迹清理卡住服务器。1.20.4存在相同实现。TrackTrail（轨迹历史）的points（轨迹点集合）是Deque（双端队列），不是List（列表）。`remove(points.size() - 1)`调用的是`remove(Object)`（按对象删除），将整数装箱后与Point（轨迹点）比较，没有删除任何元素。超过长度上限后，while（循环）的终止条件永远不变。

实际控制器采用140格历史上限。直接编译现有源码并记录0至142格，在第142格的record（记录）调用挂起，4秒超时；两版新增JUnit（单元测试）均在修复前出现两个5秒超时失败。1.20.1修复前的测试报告保存在evidence/BUG-073/mc1.20.1-before.xml。测试子进程可强制结束，避免无视中断的死循环污染后续测试。

## 修改与影响

- 两版src/main/java/cn/quit5700/fabrictrain/train/TrackTrail.java：两处错误删除改为removeLast（删除队尾），使每次循环确实减少队列元素。
- 两版src/test/java/cn/quit5700/fabrictrain/train/TrackTrailCleanupTest.java：增加独立子进程超时检查。
- 两版gradle.properties、README.md（说明）和VERSION_INFO.md（版本信息）：版本改为0.2.41-test1（测试版1），同步元数据和文档。
- 1.20.4构建控制台补充UTF-8（统一码编码）输出参数，与1.20.1既有配置一致。

不改变轨迹采样距离、140格长度上限、车厢间距、跟随插值、模型、界面或存档格式。不是关闭轨迹清理，也不通过延长上限掩盖死循环。已保留0.2.40运行包、源码包与Git历史。

## 验证与防回归

新增测试覆盖连续运行2000格并反向返回、恰好达到上限、超过上限后不能再查询过期点、大跨度一次移除多个旧点、零长度上限保留最新点、车厢2.5格位置插值。保留原有3条轨迹测试，不弱化原预期。

修复后分别运行轨迹模块5条测试，再分别执行完整test build（测试与构建）。最终数量、失败和跳过统计，以每版dist/0.2.41-test1/验证结果.json及原始XML（测试报告）为准。运行包和源码包同时校验版本及归档完整性。

实际服务器存档未在本轮加载。已复现并修复相同代码路径的死循环，但不声称排除了该服务器所有其他卡顿原因。推荐用户换包后验证列车累计运行超过140格及长编组跟随。

## 下次避免

集合类型迁移时必须检查删除方法的重载语义，不能把队列当作列表按下标删除。循环内每次删除须推进终止条件。长度裁剪测试必须跨过实际业务上限，不能只测试10格记录／20格上限。集合扫描与单次成本优化需有新的性能证据，不能顺便重写正常跟随逻辑。
