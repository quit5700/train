# BUG-120 · 十版创造授权残留与缺货后补库存不重试

类型：状态配置、保存读取、自动发车。当前项目根目录：Fabric模拟火车模组。范围为十个受支持版本，计划测试版0.2.42-test41。

现象：创造模式配置过车辆段，切换生存后空库存仍能自动补车；首次以生存／冒险模式保存缺货车辆段，补足库存后不会自动发车。

复现与根因：26.3实际客户端、真实服务器玩家以创造模式保存空车辆段后切换生存，旧test40仍发出下一列。车辆段和未加载后台使用保存时的creative标记，没有跟踪操作者当前模式。补充冒险模式首次空库存保存的实测，test41修复前的empty_save_keeps_automatic_enabled=false：自动计划仅在立即生成成功时才开启，缺货导致后续调度根本不进入重试。

修复：DispatchAuthorityService记录操作者及最后观察到的模式；在线时以实际当前模式判断，退出时刷新，兼容旧单人存档。未知多人授权不允许免费生成。加载区块与未加载后台共用授权判断。有效且运行中的自动线路保存后保留自动计划，即使缺库存也继续按间隔重试；达到上限同样保留补车计划。零上限、无线路、暂停线路和校验失败不借此强制启用。

涉及文件：各版network/DepotNetworking.java、depot/DepotDispatchService.java、depot/DispatchAuthorityService.java、block/entity/TrainDepotBlockEntity.java、offline/InfrastructureData.java、offline/InfrastructureService.java；新增depot/DispatchAuthoritySavedTest.java。只给InfrastructureData增加可选兼容字段，不改编组或货物。

验证完成：十版模式切换真实列车发车／自然卸载／库存扣除／回收各10项，十版冒险首次缺货保存→仅补车头→补齐车厢→自动发车→终点回收各9项，全部通过。最终源码3521项单元检查均通过，包含30项新增授权持久化与上限回归；全部客户端证据匹配最终运行包校验值。创造不扣，生存／冒险完整扣，原编组、货物、界面和资源保持原功能。

已尝试失败：直接替换已加载调度调用点使原AutomaticDispatchContinuationContractTest失败；恢复原调用点，在原creativeAutomaticDispatch入口中统一授权。未删除或弱化旧测试。诊断工具曾在完成时被每20刻进度输出覆盖complete字段，属于测试工具缺陷，已用!done保护并重跑；不能把缺少最终完成标记当作通过。

避免重复：首次缺货保存与成功发车后缺货必须分别测试；只测创造保存成功后的补货不能覆盖首次失败的自动计划状态。缺任意车辆时不允许部分扣库存，补齐必须无需重置发车。

构建工具记录：首次补货重试补丁写入时，Python默认换行变为CRLF，导致原源码契约精确LF断言失败。已尝试失败，修正工具为UTF-8且newline=LF，保留原测试正确预期后十版全通过。发布源码归档经旧版Loom映射后会改变游戏符号名，不能逐字与原命名源码比较；用原命名开发源码归档核对工程，再核对发布源码归档与构建输出哈希，完整工程另行保留。
