# BUG-089：线路出向必须统一按可见红三角固定基准

项目根目录：`C:/Users/quit5700/Documents/mc虚拟线路模组/Fabric模拟火车模组`。分类：方向基准／配置语义／可见状态与旧设备记录一致性。用户于2026-11-03明确选择“以红三角固定方向为准”，并要求十版同步。交付候选0.2.42-test7，保留已经交付且十一个位置均安装完成的test6，不覆盖历史包。

## 原因与准确复现

test6只把同一道岔首次实际驶入作为本线路固定基准，仍可能与可见红三角不一致。追加14项真实服务器场景后，test6四种旋转下首次侧向进入均失败，且翻转可见红三角未改变线路直行判断，证明不满足用户这次明确规则。见`evidence/BUG-089/固定方向-26.3-0.2.42-test6.json`。同一报告中，原用户线路、重复节点出向、真实断轨与回收轨道检查仍成立，不能把旧版说成所有情况都不通。

另复现：旧设备登记仍为道岔，而实际方块已被替换成信号轨时，旧实现读取不存在的入口属性会抛异常。新入口读取前检查属性，返回正常的轨道无效结果，不把无红三角的方块当成有效道岔。

## 修复及规则

十版`route/WorldLineValidator.java`直接读取与三种道岔模型旋转共用的`entry_direction`（道岔可见固定朝向）。`exitFor`把该入口的反向视作红三角所指直行，再解释左／直／右。既不采用当前车头方向，也不采用首次驶入方向；旧设备记录不能覆盖画面上的固定标记。

移除仅为test6首次驶入缓存新增的`SwitchRouteDirectionContext.java`；替换新版本的`RepeatedSwitchDirectionTest`三项契约，分别验证渲染与路由使用同一属性、四旋转下的十二个出向、重复节点仍分别保存选择。没有删掉其他正确测试或修改其预期。原`AutomaticIncomingDirectionTest`仍验证辅助方法的实际驶入几何计算，该辅助方法不再决定自动线路出向。

真实驶入信息继续传给路径扫描器，用于禁止原路掉头和构造实际轨迹；不跳过真实断轨、供电、库存、编组空间和回收容量检查。保留test6的非循环终点步长钳位、整列回收和全部其他功能。模型、材质、图标和红三角几何完全沿用用户已确认的test6基线，不重新绘制。

用户报告的实际“道岔4→站点2→道岔3→道岔4→车辆段1回收”无需修改。更早按车头行进方向配置、且固定标记与其相反的其他线路，需按这次明确的新标准复核；不自动改用户节点、箭头或车辆段位置来绕过校验。

## 失败方案与防重复

- 已尝试失败：只固定首次实际驶入的test6方案，仍不符合“看红三角”的要求；不得再次以首次方向作为线路基准。
- 不以设备保存的旧入口或`placement_entry`（旧摆放入口）代替当前模型实际使用的`entry_direction`；已经增加保存记录与可见标记不一致的检查。
- 诊断工具初次换证据目录时未复制快照，出现NoSuchFileException（找不到文件），不是模组故障。失败保留`诊断未复制快照-失败.json`；工具现先确认本项目快照存在，且必须完成全部14项才接受基线，不能把未运行的场景当成红灯复现。
- 旧BUG-084、BUG-087的首次驶入方向规则有明确版本适用范围；本轮用户新指令替换其出向基准要求，保留真实驶入的物理几何与反掉头限制。
