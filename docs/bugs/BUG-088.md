# BUG-088：非循环线路最后一次步长溢出，提前停在回收车辆段前

项目根目录：本Git仓库根目录。分类：实际运行／非循环线路终点边界。版本范围：十版0.2.42-test6，本轮用户授权一起处理发车、线路误判与终点回收。

## 复现与根因

BUG-087线路校验、生成及回收服务调用均通过后，增加真实服务器逐刻行车，不直接调用回收。原92格布局、原5秒停站、正常发电机供电下，车头在x=72.40768398636494停住，回收车辆段中心为x=73.5；800刻后无回收。设备进度已为4（正确等待最后的车辆段），automatic_running为false（自动运行已关闭），并不是漏站或重复节点进度丢失。

`RailMotionCursor.advanceRoute`在本刻距离超过最后一段剩余长度时，内部已把current推进到终点，但发现next为空就返回null。上层把它当作断轨，并在移动实体到终点之前停掉自动运行。因此车头仍停在前一刻位置，永远不会进入终点回收判断。失败证据在BUG-087目录`实际行车-终点步长溢出-修复前.json`及实际行车报告。

## 修复

十版`train/RailMotionCursor.java`：非循环线路合法到达终点时把位置钳在终点中心，消费剩余正向距离，保留最后一段的朝向。后续正向调用在仍有真实终点铁轨时返回同一终点姿态，由正常节点处理执行回收。真正轨道缺失、循环线路、反向越界及无线路自由运动分支不放宽。

不扩大回收半径，不直接远程回收未到达车辆段的列车，不改变车辆段库存满时的原安全规则。自动线路必须实际走到最后节点，回收库存必须精确包含1个车头和3节客车物品。

## 诊断场景失败记录

首次新增行车工具只强制写了供电缓存，却没有给临时发电机放燃料；下一刻真实方块实体关闭供电，列车停在出库位置。这是诊断环境初始化问题，已在工具给临时发电机放入真实红石块，未据此修改生产供电代码。失败证据`实际行车-诊断燃料未初始化-失败.json`保留，不重复使用无燃料缓存假供电进行持续行车测试。

## 验证

每版全量回归、24项历史专项、7项实际线路校验/生成/回收专项；另以`tools/probe_revisit_flight.py`真实运行完整线路，必须自然到达终点、整列实体移除，且车辆段库存精确收到1车头、3客车。结果仍须匹配最终源码指纹。未验证的客户端表现应由交付说明明确，不能用一版检查替代全部十版。
