# BUG-108 · 1.21.10 列车列表暂停单人世界

- 分类：客户端设置页与单人世界暂停。
- 现象：乘第一列到回收车辆段后打开列表，第二列长期留在列表及当前坐标。旧版实测列表打开期间游戏时间固定，关掉后同一列车继续。旧版完整乘车且全程不打开列表的对照可正常回收。
- 根因：`TrainListScreen` 继承了基础界面的暂停默认值。客户端仍显示列车列表，但单人服务端不推进游戏刻、行车与到站回收。
- 修改文件：`src/client/java/cn/quit5700/fabrictrain/client/TrainListScreen.java`。列车列表打开时保持世界运行，继续使用原有列表自动刷新。
- 验证：用真实「测试宝箱」副本让首列载人到终点，列表打开时等第二列跨至终点并核对车辆入库、列表条目消失。旧版与最终包同地图对照，保留原存档。第9、10、12、13列已重置，仅用同线路后续列车验证。
- 防回归：分别测试打开和关闭列表时的游戏时间和运行状态，同时核对终点实物库存，不能只观察历史站名或列表行数。

### test46阶段发现与最终验证范围

旧1.20.4运行包实测复现：货场页保持80个客户端刻，服务端仅在打开初期前进2刻、原车位移0.1格，暂停标记为true；不是供电或轨道问题。阶段13页候选在1.20.1／1.20.4通过后，静态检查另发现铁路管理页右键线路所打开的原版ConfirmScreen（确认窗口）仍默认暂停，故同文件追加匿名不暂停覆盖，并扩大为14页、56项真实断言。旧13页候选的成功不作为最终包通过依据；旧矩阵仅终止了本轮独立客户端，没有结束玩家游戏。最终14页按重新构建运行包散列逐版重测。

诊断工具已尝试失败：自定义车头类型调用继承原版Entity（实体）方法时，独立探针重映射漏掉继承方法并报NoSuchMethodError；改成显式原版Entity类型，非生产代码变更。工具异常不作为缺陷复现通过。


最终矩阵工具修正：1.20.1的14页断言通过后，完整环境保存退出超过原进程300秒时限，未取得干净退出故不计最终通过；进程等待放宽600秒，不改80客户端刻、世界时间、位移及乘坐断言。1.20.4反射按参数选中mouseReleased（鼠标释放）而未打开确认页，已尝试失败；旧版按下与释放签名相同，改为检查实际ConfirmScreen（确认窗口）已打开再计时，非生产变更。两版重跑最终场景。


诊断环境适配：旧test42诊断工程在1.21.4配置layered mappings（分层映射）时报IO失败，未取得底层栈，不能认定为业务缺陷；参照本项目BUG-113／123的同类缓存记录，不改映射版本、不删除缓存。后续诊断改在本轮已完整构建通过的对应test46工程执行remapJar（重映射归档），仅输出独立探针，补--stacktrace保存底层证据。最终运行包散列仍单独核对，诊断失败不计通过。


26.3诊断鼠标版本差异已确定：本地实际SDK的InputConstants（输入常量）经javap核验，26.1.2右键=1、26.3右键=3／左键=1。探针旧值1实际左键选中线路，故仍是管理页面而非确认框；不是默认暂停覆盖失效。生产页原本已按版本使用对应常量，保留不改。仅增加页面等待的探针在进入世界前原生退出，未取得页面验证；据SDK常量可确定，仅等待不能把左键1变成右键3；此前关于选中编号0的猜测被真实副本线路ID1至4否定。26.x诊断源码编译时直接读取本版常量，修正后完整重测26.3。


26.3第二次诊断启动在进入世界前以3221225477（原生访问冲突）退出，没有result.json；不是一次页面断言通过。运行包初始与复制后散列一致，保留启动核验和客户端日志，原生退出根因未确定，不修改驱动或无关模组，也不声称修好此原生问题。第三次采用相同生产包及已修正鼠标常量的探针独立启动验证。


## 0.2.42-test46 最终结果

根因：八类普通设置页继承Screen（基础界面）暂停默认值；前次只覆盖列表。修改文件：各版client（客户端）下CargoSettingsScreen、DepotSettingsScreen、DeviceSettingsScreen、FormationScreen、FreightYardScreen、LineSettingsScreen、RailwayManagerScreen、TrainClassScreen，仅新增isPauseScreen返回false；同文件的删除线路确认窗口也覆盖为不暂停。

十版完整自动回归4017项通过；每版14类页面真实自动列车试验，共140页、560项时间／位移／原车乘坐／暂停标记断言通过。普通箱子沿原版右键路径验证，不改原版容器。十个主要实例已安装，其他功能与玩家原档未改。旧包复现和最终包散列一致证据见[交付说明](../设置界面不暂停_0.2.42-test46.md)。

确认窗口在静态复核中发现默认暂停，补充实际右键线路列表打开确认窗口的测试；已通过13页的旧候选仅作阶段证据，最终14页按新运行包散列全部重跑。

测试工具已尝试失败：直接以自定义车头类型调用继承原版方法会漏重映射，产生NoSuchMethodError；改以原版Entity（实体）类型调用，仅修诊断工具，失败不计通过。旧版鼠标按下与释放方法参数完全相同，诊断改为逐一检查实际打开确认页；完整模组启动和退出保存可能超过300秒，工具进程等待放宽600秒，而各页80客户端刻及世界位移断言不变；超时结果不计最终通过。26.3诊断右键旧值1实际为左键，本地SDK核验右键为3；生成26.x探针时改读本版输入常量，生产代码已使用正确常量，无需再改。26.3曾在进世界前发生一次原生访问冲突退出，未计通过，日志保留，未声称修复其底层原因；相同生产包独立重测。后续不得用服务端单边计时或自动关闭界面证明不暂停，必须同时观察客户端时间和服务端实体位移。
