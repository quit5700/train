# BUG-094：远处轨道主动加载后的供电缓存陈旧

当前项目根目录：本Git仓库。类型：状态缓存／区块加载时序。影响：26.3已复现；共用主动发车路径同步十版防护。test9实际引擎红灯已复现；test10最终验证以末节和交付说明为准。

现象：发电机运行、线路完整，远处车站和回收车辆段已自然卸载。点击自动生成，第一次校验返回UNPOWERED（未供电），随后重新刷新并校验却通过。不能由该结果推断发电机库存没有红石粉。

根因：DepotNetworking在主动线路验证前刷新供电；WorldLineValidator.validateDetailed随后通过同步读取加载远处轨道并建立新的PowerSectionCache。此时远处轨道尚未进入之前只遍历已加载区块的RailPowerService结果，因此新建立的分段供电缓存被标记未供电。区块卸载是既有离线功能的正常条件，不能恢复永久加载掩盖此问题。

红灯证据：docs/bugs/evidence/BUG-093/生成与供电-26.3-red.json，运行包0.2.42-test9。原生12区块半径下起点加载、远处设备自然卸载；第一次validateForImmediateDispatchDetailed返回UNPOWERED且allPowered为false，第二次实际刷新后READY。同一程序也真实重放客货车5节缺轨、补轨成功、重复生成占位与旧车移开后再次成功。

最小修复：十版WorldLineValidator.java的validateDispatchAccess在完整接入路径扫描结束后、计算返回的供电状态前刷新供电；上层完成整条线路拓扑验证后再次调用时，也覆盖刚加载的远端轨道。仅主动发车路径执行；后台LoadedRailWorld无票据读取与离线自然卸载保持，不为校验失败而删除轨道或货物。燃料不足的真实未供电检查保留。

验证策略：逐版实际引擎长线路首次发车校验必须READY，再校验仍READY；保留原生卸载、10分钟离线到站及真实重载交付、原有方向/断轨/回收回归。逐版完整构建与单元检查、旧版Java17/21生产启动及八语言资源校验。最终结果待交付回填，不以单版编译代替十版通过。

诊断工具首次编译失败：PowerGenerationChecks.java漏导入route包的WorldLineValidator，补齐明确导入后编译并完成真实服务器重放。该失败属于诊断代码导入错误，不是运行模组适配失败；禁止修改生产接口绕过遗漏导入。

防回归：任何主动读取会加载线路区块的操作之后，必须刷新依赖已加载区块内容的供电结果；不得只保留验证前的刷新。出现“第一次失败、再试通过”时检查读取与缓存重建的先后顺序。区分未加载、未知与明确未供电；不能将通用提示写成“缺少红石粉”。

已尝试失败：仅在validateDetailed结束后、validateDispatchAccess之前刷新，在26.3通过，但1.20.1/1.21.1/1.21.4/1.21.8真实回归仍返回未供电。失败报告及原日志已保存到本缺陷证据目录。接入段扫描同样会读取加载轨道，最终刷新位置必须覆盖全部扫描。不能拿26.3单版通过覆盖旧版本失败。

补充判定：上述旧版失败场景中，PLAYER加载票据未让起点发电机持续更新，保存数据显示最后一次燃料结算停在第300刻，700刻时生成器登记被40刻过期逻辑清理。校正为仅在独立临时世界让起点持续更新，并在结束前撤销临时票据；新增真实发电机700刻后仍active且有燃料的断言。校正场景下1.21.4 test9本来可通过供电，因此不能把旧版初版失败证据当成同一生产缺陷已在旧版复现。26.3 test9使用PLAYER_SIMULATION真实模拟更新，原红灯有效；26.3 test10真实通过，其他版同步防护并分别验证。临时更新票据与数据不会写入用户存档；生产模组不新增强制加载。

最终诊断统一条件：1.21.8即使有同名加载/模拟票据，仍可能只有active缓存字段保持true而真实方块更新停止。为避免仅检查缓存字段，现用lastObservedGameTime与当前游戏时间相差不超过1刻验证持续更新；所有版本仅在独立测试世界对起点和预加载的生成区使用相同临时更新条件，结束前全部撤销。诊断源码另计算SHA-256（摘要），最终证据同时绑定生产源码与诊断源码，旧场景通过报告不得直接复用。原26.3红灯保存的RemainingFuelTicks=503342、FuelUntilGameTime=504042，对应第700刻刚更新，排除发电机停更造成的假红灯。
