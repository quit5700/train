# BUG-076：合并火车与通行功能的版本接口适配

项目根：Fabric模拟火车模组。分类：版本适配／编译。仅记录本仓库本次实际发生的问题，不导入其他项目的缺陷记录。

现象：新增26.3本体初编译有8项错误，方块simpleCodec/codec接口已删除，InputConstants.isKeyDown只接收按键值；1.21.10初编译从1.21.11复用本体时出现矿车包和Identifier不存在，引发大量继承连锁错误。

根因：新旧游戏版本的平台接口和命名不同；不是火车数据或通行核心算法错误。使用本机实际目标游戏类声明核对，编译为稳定可复现的反馈环，明确不存在的符号不进行无证据的大范围重写。

修改：versions/0.2.42-test1/mc26.3的PowerGeneratorBlock、TrainDepotBlock、FabricTrainClient及输入混入；1.21.10本体相关Java源码的ResourceLocation/矿车类引用。只改版本专用声明，保留其余原逻辑和模型。

修复：26.3移除被删除的方块编解码接口、使用单参数isKeyDown；1.21.10恢复ResourceLocation与net.minecraft.world.entity.vehicle矿车包。后续实际错误继续按根因分类补充。

已尝试失败：26.3直接沿用26.2旧方块和按键声明；1.21.10直接使用1.21.11的Identifier和vehicle.minecart包。禁止再次原样套用。

验证：原始失败编译日志保留在对应新版本目录，修复后按版完整构建、全部旧回归、通行回归及专用服务器保存重载；结果以各版交付报告为准，不能仅凭能编译声称实机正确。

防重复：共用功能与接口差异分开，各版源码独立。轨迹清理继续保留BUG-073的140格上限子进程测试，不用新功能覆盖既有修复。

进一步核对：1.21.10的Screen为单参数标题构造器，GuiGraphics使用submitOutline，实体同步标记为hurtMarked；26.3铁路管理页的左右鼠标按钮必须使用InputConstants的SDL常量，不能继续用旧0／1。已只在目标版本适配，其他版本原接口保留。

1.20本体还使用独立fabric-blockrenderlayer-v1模块，仅加入rendering-v1不能覆盖该接口；通过扫描当前已安装完整API中的实际类归属，补齐各版源码所需模块。未把全量API下载名字当作子模块坐标。

新增范围渲染复用已成功的快捷建造源码实现，不读取其BUG记录。版本接口：1.20／1.21早期用WorldRenderEvents.AFTER_TRANSLUCENT与直接缓冲；1.21.10／1.21.11用world事件及commandQueue；26系列用level事件及submitNodeCollector。不可把三个接口互相覆盖。初次26.3构建另有RangeController遗漏ClientPlayNetworking导入，按普通Java语法问题补齐，未改网络协议。

26.1.2的范围列表辅助按钮必须使用GuiGraphicsExtractor及text，虽然其Minecraft.screen仍是旧访问方式。已尝试失败：简单把“26.2起才用新图形接口”作为统一分界。正确做法是分别根据本版既有已编译AccessScreen的声明选择图形与屏幕访问接口，不将两种迁移绑定。
