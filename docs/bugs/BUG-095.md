# BUG-095：真实自动货车卸载交接与车辆段离线发车

项目根目录：本Git仓库。用户授权：十版一起修，以实际生成自动货车自然离开加载区域、移走起点加载区域、真实停服重启及重新加载的完整流程验证，不再用手工构造OfflineTrainState（离线列车状态）代替交接。开发版本0.2.42-test11。

已确认代码缺口：DepotDispatchService.tick直接跳过未加载的车辆段；TrainControllerManager只在下一轨道区块未加载时调用transition，实体整体被卸载时noteVehicleRemoved只记录UNLOADED，运行路径随后被清理；RailPowerService按40刻登记时效删除未更新发电机，不能用该登记时效代表燃料失效。现象为货车等待玩家加载才继续，以及玩家离开起点不再自动发车。

本次范围：自然卸载前的完整编组/货物权威交接；持久化车辆段配置、已验证线路与库存；无玩家时的虚拟调度和电力燃料结算；回收与箱子加载后的单次交付；重新加载时丢弃已经交接的旧实体副本，恢复权威库存。保留手动模式、0上限、发车间隔、数量上限、真实断轨、物品守恒、旧版refmap（混入引用映射）与原界面模型。

不以永久强制加载作为运行修复。测试工具可用有限的临时观察区域加载票据模拟玩家视野，必须在观察阶段移走起点票据，断言发电机、车辆段、轨道和箱子实际卸载；列车由公开的真实生成入口创建并消耗真实车辆库存，按正常游戏刻运动，不调私有advance、不改游戏时间、不直接创建离线状态。旧包先复现失败，再在相同流程验证新包。

验证中，完成后记录根因、修改文件、失败方案、各版结果和未验证风险。

开发中失败记录：26.3 CHUNK_LOAD（区块加载）事件的回调仍处于完整区块期程结束之前；在回调内恢复容器会调用setChanged，递归等待同一区块完成，触发服务器看门狗。已尝试失败，禁止再次在该回调内写容器。改为服务端正常游戏刻、以及交易前的加载容器绑定恢复。证据：outputs/natural-cargo11-26.3-debug1-1793979918/crash-reports/。此次为独立测试世界，未安装或触碰用户存档。
版本适配：26.3 ServerChunkEvents.CHUNK_LOAD回调新增isNew参数，直接使用双参数方法引用编译失败；26.3使用三参数lambda，旧版仍用双参数。Windows PowerShell不使用Bash花括号路径展开，rg也不使用未展开的通配符路径，改用带引号的实际目录。
旧版接口记录：1.20.1/1.20.4的getItems定义在RandomizableContainerBlockEntity，不能将新版本BaseContainerBlockEntity访问器原样复制；旧版专用访问器目标与命名映射分别验证。
真实重载失败记录：卸载回调发生时LoadedRailWorld已不再提供该区块，使用它记录容器方块种类得到air，导致重载时权威库存匹配失败；迟到/重复卸载回调还可能以旧物理库存覆盖已经虚拟结算的库存。改用BlockEntity自身保存的BlockState记录种类，且只允许仍绑定的同一个物理容器在非停服阶段提交一次卸载快照；停服阶段已在STOPPING事件统一提交，后续卸载禁止覆盖。证据：debug3自然货运保存与真实重载结果以及offline_infrastructure.dat。测试等待时间按448格货车正常速度至少1120刻计算，首程观察延长至1800刻，不修改游戏时钟。
接口适配：1.21.8/1.21.10/1.21.11的SavedDataType首参是String（字符串），26.x改为Identifier（标识符）。按各版本已有OfflineTrainSavedData成功实现保持相同标识格式，不重复使用26.x构造方式。26.1.2/26.2所用生命周期接口与26.3一样，CHUNK_LOAD需要第三个isNew参数。
附带守恒约束：后台容器镜像保留真实容器的放入限制，发电机只接受红石燃料；未知远端容器不猜测槽位规则，回收首先使用车辆段及已识别箱子。原有停站等待会随运行检查点保存，并在重新实体化时恢复；实体货车卸货也通过同一库存权威记录，避免恢复旧箱子内容。新增4项持久化单元回归，真实流程末程往返加载检查额外覆盖3项。
旧行车测试时序适配：新功能允许原始实体在自然交接时被移除，旧探针误把“原实体都移除”立即等同于“到达终点”，在1.21.x提前核对回收库存失败。保留历史探针不变，新增test11探针继续等待真实回收；仍必须恰好一个车头、三节客车，并额外要求自动配额和离线状态均清理，不降低任何正确预期。
多道岔重启一致性：签名使用Map.toString，而RailwayLine内部Map.copyOf不保证跨进程遍历顺序，未改线路也可能出现签名不一致。已以canonical（规范顺序）单元回归复现失败，证据见线路签名顺序-red.xml；修复为按节点索引TreeMap排序后生成签名，保留新增第五项持久化回归。最终真实货运线加入三处显式道岔方向，在两个真实服务器进程之间核对。
最终数量检查同时计算世界中的物品掉落实体，不能仅计算箱子和车厢而漏掉重复掉落；车头和货车的多余掉落也视为重复车辆失败。
观察场景修正：跨版实际进度不同，固定重启后第400刻观察会错过真实货车，或在第430刻单点检查时车已再次离开观察范围，错误报实体化失败。改为在真实第三列刚发出、源设施均已真实卸载时保存，并在列车实际进入指定远端路段时靠近；等待完整两实体出现后再离开。仍要求所有28项通过，不调游戏时间、不构造离线列车、不放宽库存和回收数量。
26.2完整回归曾在六路并行时出现一次canSeeSky光照完成时机检查失败，原始日志已保留；没有改动测试断言或业务代码，单独重新运行相同完整构建和服务器检查，结果以最终指纹匹配报告为准。
