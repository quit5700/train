# BUG-083：26.3范围列表字体候选的细笔画与字体授权资源路径

当前项目根目录：`C:/Users/quit5700/Documents/mc虚拟线路模组/Fabric模拟火车模组`。

分类：客户端显示／资源标识路径。范围：0.2.42-test3候选，未安装失败候选。

## 现象与根本原因

用户要求修改26.3范围列表字体。第一次候选客户端实际截图显示中文笔画太细，部分笔画在小字号下丢失。字体表读回确认上游Noto Sans SC可变字体默认wght=100；游戏默认取该实例，不能假定下载的是常规字重。

客户端同时报告`Invalid path ... font/OFL-NotoSansSC.txt`（无效路径）：字体许可证原文件名带大写，违反游戏资源标识只接受小写字符的规则。这与Windows是否能读取文件无关。

## 涉及文件与修复

- `versions/0.2.42-test3/mc26.3/src/main/resources/assets/station_access/font/noto_sans_sc.ttf`：使用fontTools（字体处理工具）4.68.0将wght固定为500，保留完整字符集合。
- 同目录`range_ui.json`与客户端`RangeListScreen.java`：只对本页指定字体，原版字体作为缺失字形后备，不覆盖全游戏字体。
- 许可证移至`src/main/resources/META-INF/licenses/noto-sans-sc-ofl.txt`，不占用游戏资源命名空间。原字体与许可证保存在`design/fonts/noto-sans-sc`。
- `UiResourcePathsTest.java`：检查所有游戏资源相对路径符合小写标识规则，检查字体许可证存在。
- `tools/refine_ui_font_test3.py`：记录可重复的固定字重与许可处理步骤。

已尝试失败：直接使用可变字体默认实例显示小字号中文；把上游大写许可文件名原样放在assets目录。不得重复采用。

## 验证

原候选截图和日志保留在`outputs/ui-test3-1793630344`。最终构建、单元测试、服务器保存/重载结果见本次版本`验证结果.json`；最终客户端截图见`docs/验证截图/0.2.42-test3`。交付前必须检查最终客户端无本模组资源路径或字体加载错误，并人工确认文字完整。

最终结果：295项单元检查、66项服务器功能、6项保存重载共367项通过；实际客户端截图确认字形完整，最终日志无本模组字体加载及资源路径错误。已安装26.3指定目录。其余九版本次未改；实际世界交互仍由用户测试。

## 防止重复与影响

后续跨版本字体复用使用已固定字重的字体，不重新取默认变量实例。第三方文档许可放META-INF，游戏资源路径全部小写。新字体仅影响26.3范围列表，不改通行判断、轨道、列车控制、存档格式。用户澄清车站/道岔交互只是忘记操作，不作为缺陷处理。
