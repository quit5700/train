# BUG-077：合并版测试缺少游戏类路径

当前项目根：Fabric模拟火车模组。分类：Gradle测试配置／中文路径。

现象：26.2编译通过，但JUnit发现RailwaySavedDataTest时抛出NoClassDefFoundError: net/minecraft/world/level/saveddata/SavedData。失败XML保存在evidence/BUG-077/mc26.2-classpath-before.xml。

根因：原通行单元测试只需独立几何／账本及资源，火车旧测试还依赖真实游戏SavedData；新构建配置的testRuntimeClasspath/runtimeClasspath不一定包含Loom专用游戏运行归档。不能把缺失类误判为火车业务失败，也不能删掉这些旧测试。

修复文件：新10版build.gradle。syncAsciiTests同步runServer真实运行类路径中的JAR到纯英文临时runtime-jars目录，Test类路径引用这些已同步归档。原有中文项目路径仍为实际编译与工作目录，不改文件编码或系统全局设置。

已尝试失败：仅加入configurations.runtimeClasspath仍缺少Minecraft SavedData类。禁止删除或跳过旧存档测试来通过构建。

验证：每版重新完整test/build，原存档测试、通行检查和轨迹清理测试均必须执行，随后专用服务器保存重载。结果见各版报告。

预防：合并测试集时先区分纯逻辑测试与依赖游戏类型的测试，核对实际运行任务类路径，而非推测配置名称含有哪些归档。

进一步检查：Windows文本写出默认转CRLF，使原先按LF检索的自动发车源码契约误报；新源码统一显式LF换行，未修改测试预期。旧普通聊天静默检查将新模块displayClientMessage(...,true)误算普通聊天；保留普通聊天4处、连接器3处的正确预期，改用平衡括号识别真正的overlay参数，并增加true不计入／false计入的回归。分发任务恢复copyDistribution，旧版明确依赖remapJar及remapSourcesJar，避免交付开发命名包。

交付补充：本机Git的自动换行设置提示未来检出会把LF源码转换为CRLF，可能再次触发此前源码契约误报。已在本项目.gitattributes显式规定Java/JSON/Gradle/Python/文档采用LF，批处理采用CRLF，未改全局Git配置或现有测试预期。当前通过检查的源码字节不变。
