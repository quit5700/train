# 1.21.8 自动列车区块边界停车 · 0.2.42-test28

- 现象：线路处于运行状态，第 14、15 列在站外分别停在 Z=208、148，服务端仍推进了 1066 游戏刻。
- 根因：供电遍历早于部分轨道区块可读，首次遍历截断后没有重算。单独刷新供电能恢复行驶，但第 15 列又停在 Z=223，前方区块可读但尚未执行实体更新，旧的交接条件只判断可读。
- 修复：`power/RailPowerService.java` 只记住供电遍历实际遇到的不可读区块，可读后自动重算。 `train/TrainControllerManager.java` 将前方区块不能运行实体的无人自动列车交给现有后台推进。
- 已尝试失败：单独手动刷新供电只能跨过第一个卡点，在第二个边界仍长时间停住；未将手动刷新作为最终方案。
- 验证：真实「测试宝箱」停车副本在 1.21.8 客户端重放，无手动刷新，两列越过原卡点并在 moshou 回收，终点库存增量为 {'cargo_car': 6, 'locomotive': 2, 'passenger_car': 2}。通过 462 项自动检查。
- 防回归：分别检查区块可读与实体运行状态，真实存档跨加载边界运行到回收并核对库存。
