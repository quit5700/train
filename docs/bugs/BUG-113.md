# 车辆段顶面铺轨

0.2.42-test36，十个版本同步。唯一行为变更：手持铁轨右键车辆段顶面时，让原生放置流程继续执行；与货场的判断完全一致。支持普通、动力、探测、激活四种原版铁轨以及模组信号铁轨和道岔，蹲下时也适用。生存模式成功放置扣一件，创造模式不扣；顶面被占用时不覆盖、不消耗物品。

问题分类：客户端与服务端交互优先级。旧包在独立客户端实际右键复现，顶面仍为空、手中两根铁轨未减少，却打开车辆段库存。根本原因是车辆段的全局交互、方块自身交互及潜行设置快捷键均会优先消费右键，缺少货场已有的铁轨顶面例外。

修改范围：新增DepotRailPlacement.java统一判断“顶面＋铁轨方块物品”，DeviceInteractionService.java、TrainDepotBlock.java及MinecraftUseItemMixin.java在各自车辆段分支提前放行；新增DepotRailPlacementTest.java四项自动回归。不处理侧面铺轨、不扩大其他放置规则，不改车辆段库存、设置页、发车、供电、货运或列车逻辑。模型、材质、配方、语言、注册与数据存档资源均与test35逐字节一致。

版本差异：1.20.1／1.20.4在原use方法通过当前hand判断；较新版保留useItemOn原有放行，另在useWithoutItem补齐判断。客户端混入只在车辆段分支拦截之前增加例外，保留原反射映射配置和其他设备快捷键。

验证：十版完整自动回归及新增每版四项判断测试；1.20.1、1.21.8和26.3使用独立存档副本，通过Minecraft.startUseItem原生右键入口和真实客户端／服务端数据包执行15种场景，包括六类铁轨、潜行、占位失败、原侧面与空手库存交互、其他方块物品、潜行设置入口及创造模式消耗。未以直接修改世界方块代替右键测试。其他七版未逐个进行玩家手动输入验收。

已尝试失败：测试工具首次在客户端尚未完成世界加载时就操作，出现无响应；改为确认世界状态并等待首帧就绪后，旧包稳定复现误开库存，新包逐项通过。1.20.4首次映射配置报IO失败，带栈重试时Loom明确检测到遗留缓存锁并重建，最终构建和测试通过；未改依赖或映射版本。原日志未展开首次底层IO异常，不能据此断言游戏逻辑有问题。旧版测试存档最初按另一实例目录查找失败，核对后采用同一游戏版本实际存在的测试宝箱副本；没有创建或改写用户存档。1.20.1开发启动器默认Loader为0.18.4，实际安装实例为0.19.3，带其他模组启动时被其最低版本检查拒绝；仅换Loader后还因旧Mixin缺IAdviceProvider接口失败。最终独立测试启动器复用0.19.3已验证的完整ASM／Mixin／MixinExtras依赖组合，不改游戏目录及源码构建依赖。下次不能只替换Loader单个JAR，也不能把源码构建依赖误当成实际安装环境。

防止复发：新设备交互必须检查全局回调、方块方法和客户端快捷键，避免只改其中一处。对只有顶面成立的例外，必须同时验证其余面和非铁轨保持原交互；保持原生放置负责消耗、碰撞和占位失败。保留本轮四项单元检查及15种真实右键流程。

本次仍为测试版，不上传发行版。十版独立运行包与源码包保留，各版完整依赖信息见VERSION_INFO.txt；安装到核实后的十一游戏实例，源码包不放进模组目录。

交付校验说明：旧版混入配置由构建步骤注入refmap（反射映射文件）引用，不能要求运行包配置与未处理源JSON逐字节相同；本轮按上一版运行包比较该配置，且单独断言引用文件存在。该构建注入逻辑及原有测试均未修改。
