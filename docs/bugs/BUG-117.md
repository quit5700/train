# BUG-117 · 1.21.4 主页面多出速度编辑器及货场通路核查

类型：界面入口范围、线路方向诊断。版本：0.2.42-test39（测试版）。

现象：铁路线路设置主页面左下多出客车、货车、特快三按钮、速度框和保存按钮；用户只要求保留车辆段设置中的这组控件。同时当前线路提示货场2与jin无可用轨道。

根因：早期速度入口联动时把编辑控件扩展到了铁路主页面，超出用户指定页面范围。通路问题经真实“测试宝箱”存档副本复现，货场位于(0,-61,23)，停止铁轨(0,-60,23)，jin道岔位于(0,-60,25)，中间轨道连续。出发车辆段2位于(9,-61,25)，接入路径先经过jin，再到货场，下一节点又要求返回jin。携带接入方向的搜索拒绝立即沿来路掉头。这不是货场顶轨识别失败，也不是道岔只有两侧连通。

修改文件：RailwayManagerScreen.java移除该页InlineTrainSpeedEditor、车型按钮、三个框、速度保存按钮及错误提示；恢复列表底部空白和原有线路操作区。FabricTrainClient.java移除该页面专属速度刷新分支。DepotSettingsScreen.java、TrainClassScreen.java、服务器速度数据、轨道寻路代码、模型、材质与存档格式均保持逐字一致。

验证：352项既有自动检查通过。实际客户端检查主页面仅剩线路名一个输入框、800×600缩放后控件未截断、选中线路后编辑操作保留、车辆段仍有三个速度框。保存截图并检查清晰度。运行包中除上述两个源码对应类外，其余类及全部资源逐字一致。

通路对照：同一货场到jin不携带入站方向时找到3格连续轨道；携带真实接入方向则无前向可行路径。仅在副本改用北侧车辆段4作为验证起点，完整原线路通过。建议使用车辆段4出发，或调整货场/车辆段布局保证装货后向前行驶。未自动更改用户存档、节点列表或启用原地掉头，未把“忽略入站方向”作为修复方案。该放宽方法会破坏已验收的禁止直接折返规则，不采用。

防重复：速度联动只统一数据，不代表在所有页面增加编辑器；物理相连不代表按当前节点顺序可前向行驶。遇到同类提示，检查真实接入路径和上一个节点，不能只看两节点之间有无铁轨。
