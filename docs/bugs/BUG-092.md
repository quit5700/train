# BUG-092：test9购票、手动车配额及远程测试场景

当前项目根目录：本Git仓库。范围：十版0.2.42-test9。用户明确授权补全所有帮助操作步骤、手动车不受自动配额限制、十版测试宝箱直线延长及远处设备卸载、手持票提示次数、取消票配方并由充值器购票。现有UI布局不改造。

购票检查主手优先、副手其次；没有手持票时才发新票，不能擅自给背包内其他票充值。新票需要36格主物品栏有空位，满包时不得先花最后1颗绿宝石腾空位；已有手持票满包仍能加次数。全部材料/容量/上限验证成功后再扣1绿宝石并加10次，上限30000。新票回执保存实际放入槽位，避免票放入背包后界面误显示0次。保留原recharge内部兼容入口，游戏网络购票使用新的权威交易入口。

自动数量统计使用明确的ROUTE_AUTOMATIC记录，不借用泛用activeTrainCount改变其他调用语义。手动生成不进入自动0上限回收分支，不检查自动配额；0上限回收只收所属自动列车，旧手动回收排队记录也取消。原保存重载回归保留LOADED→未确认边界，但待回收测试对象按本次明确新规则设为自动模式；不能以UNLOADED绕过原BUG-090修复。

手持提示按物品引用和服务器余额变化触发，重复同一刻不刷屏。切走再切回、换另一张票和次数变化都更新，余额以服务端为准。

## 远处区块被动加载问题

在本项目临时世界放置同坐标480格直线、起点车辆段、240格车站及相邻箱子、480格末端车辆段，并以原生12区块范围票据模拟人物留在起点。修复前26.3实际运行1000刻：起点保持加载，几何上远处均超出范围，但车站、箱子、末段全部仍加载。红灯报告为evidence/BUG-092/长直线卸载-26.3-red.json。

供电遍历在边界调用level.getBlockState，检查是否已加载发生在读取之后；红石设备轮询更直接对所有已登记设备读取相邻方块。站点容器及车辆段库存轮询使用会创建/续期UNKNOWN区块票据的Level读取。即使先hasChunkAt也不能避免对已加载区块反复续期，因此刚访问过的远程设备无法自然卸载。

最小修复引入LoadedRailWorld，使用getChunkNow及该已加载LevelChunk的直接方块/方块实体查询，不创建或续期区块票据。供电、红石、站点容器和车辆段后台轮询复用该读取。未加载时保留已有连接/供电快照及红石边沿状态；主动线路验证和玩家界面请求不在此修改范围。不会通过永久强制加载伪造离线测试。

## 开发诊断失败记录

首次新长线诊断编译命令漏了javac虚拟机stdout/stderr编码参数，读取中文错误时解码失败；修正为与已有验证器相同的file/stdout/stderr UTF-8。26.3的ChunkPos记录不接受BlockPos构造，改用所有版本均支持的两个整数区块坐标。临时票据按各版本实际API分别调用旧addRegionTicket或新addTicketWithRadius；新版本同时模拟PLAYER_LOADING与PLAYER_SIMULATION并持续更新，旧版使用PLAYER。不能直接用新版接口覆盖旧版。

## 既有离线到站卸货补测

此项是用户确认的旧规则补测，不是新增需求。计划以游戏时间10分钟到站，11999刻时货车仍有64件且无账本，12000刻到站后车厢清空并仅产生一笔64件待交付记录；站点和箱子仍未加载。后续实际停止服务器并重启，加载箱子后完整交付64件、账本清除，重复调用交付不增加物品。剩余待交付货物位于账本，而非已经离站的货车；未加载箱子不会被强写。诊断使用生产OfflineTrainService.advance（离线运行推进器）与真实保存数据，仅在临时世界控制游戏时钟，不改用户世界时间。

诊断构造曾失败，均为已尝试失败方案：起点与终点同时作为线路内车辆段节点，触发“只能有一个回收车辆段”正确限制；改为站点在节点0又与OfflineTrainState最小nextNodeIndex为1的既有约定不符，导致测试跳过站点。最终使用真实起点道岔作为节点0、站点节点1、回收段节点2，出发段单独绑定线路。此起点测试道岔仅位于独立临时世界，实际用户授权长线仍铺设信号铁轨，旧道岔不变。这两个诊断错误不作为生产运行缺陷，也不修改正确生产限制。

主要修改文件（各版本同模块分别适配）：stationaccess/Transactions.java、AccessNetwork.java、TicketHud.java、AccessService.java、HelpCompat.java；fabrictrain/data/RailwaySavedData.java、LoadedRailWorld.java、depot/DepotDispatchService.java、DepotRecallService.java、network/DepotNetworking.java、compat/TrainHelpCompat.java，以及供电、红石、容器后台轮询对应文件。删除车票配方，更新八语言操作说明，新增购票/提示/配额/帮助/配方回归测试。原模型和界面布局资源逐字节保留。

防重复：后台读取不得先调用会续期加载的Level接口再判断加载状态；不得以hasChunkAt加Level.getBlockState组合代替无票据读取。人工构造离线状态须遵守真实线路首节点和唯一回收段约定，失败时检查测试输入，禁止为通过诊断删除正确生产限制。保存重载必须是真正关闭再启动，不能只测试序列化对象往返。
