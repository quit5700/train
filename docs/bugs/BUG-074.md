# BUG-074：本轮构建依赖及中文输出

分类：Gradle（构建工具）依赖解析／中文编码。当前项目根目录为Fabric模拟火车模组Git（版本管理）仓库。

1.20.1执行测试时，minecraftNamedRuntime（游戏运行依赖）解析要求四个缺失的LWJGL（轻量Java游戏库）3.3.1本地库文件，游戏库站点连接出现TLS（传输层安全）握手中断。测试任务尚未运行，不能当作轨迹测试失败。Python（派森）HTTPS下载也失败；此方案已尝试失败。本轮通过PowerShell（命令行）从Maven Central（中央依赖仓库）取得同版本文件，并校验该仓库提供的SHA-1（摘要）。未关闭TLS证书验证，也未删除或跳过测试。

四项校验结果：

- lwjgl-glfw windows-x86：b997e3391d6ce8f05487e7335d95c606043884a1
- lwjgl-jemalloc windows-arm64：cae85c4edb219c88b6a0c26a87955ad98dc9519d
- lwjgl-opengl windows-arm64：527d78f1e9056aff3ed02ce93019c73c5e8f1721
- lwjgl-stb windows-x86：a8d41f419eecb430b7c91ea2ce2c5c451cae2091

仅把文件写入Gradle内容缓存再执行offline（离线）模式仍失败，因为缺少该远程仓库的解析记录；标记为已尝试失败。解决方式是用tools/verified-lwjgl.init.gradle（本地依赖初始化）明确指向outputs/verified-lwjgl-repository（本地镜像），只替换org.lwjgl（库组）来源，库版本及文件内容不变。现有Minecraft直接依赖缓存没有POM（项目依赖说明），本地仓库必须用artifact（文件）元数据来源；仅默认POM解析已尝试失败。

初始化脚本参数必须使用绝对路径，因为Gradle的-p（项目目录）会改变相对脚本路径解析。日志中中文显示异常与真实路径不存在须分别判断。本轮两版的编译器诊断出现乱码；Windows原生命令行活动代码页为936，外层输出按UTF-8读取。仅补充Gradle守护进程的sun.stdout.encoding／sun.stderr.encoding（标准输出／错误输出编码）不能解决包装器与子进程编码不一致，标记为已尝试不足。除统一这些配置外，tools/构建轨迹修复测试版.ps1（构建脚本）在本次构建进程中设置65001代码页，并用JAVA_TOOL_OPTIONS（Java启动参数）向包装器及子进程统一传递UTF-8输出参数。使用中文路径、中文类名及字段的故意缺失类型编译样本检查，中文“错误：找不到符号”和完整路径显示正确；该样本预期编译失败，不是模组构建失败。没有修改系统永久编码设置，不把中文路径或编码问题归咎于用户。

完整验证见每版交付报告；本地依赖镜像与脚本随交接保留。后续先查本记录，不重复直接缓存注入、跳过测试、关闭证书验证或扩大修改编译依赖的方案。

正式交付检查还发现两版历史README（说明）中0.2.36的首位误写为NUL（空字符），使文本搜索按二进制处理。只将该空字符恢复为数字0，统一UTF-8（统一码编码）写入，修正后检查无空字符；不改历史功能说明。
