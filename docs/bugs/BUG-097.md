# BUG-097 货场手持名称、铺轨与分类交互

类型：资源翻译、方块交互优先级、客户端输入与已有库存规则。

- 现象：手持货场显示原始翻译键。潜行拿铁轨右键顶面无法放置。车厢标签和物品格不能正常点击。分类页上的装货方式按钮造成歧义。
- 原因：运行包只有方块名称键。货场回调对目标方块无条件消费右键。26.3 切换到 SDL（简易直控媒体层）输入后，游戏原生按钮接收左键编号 1，旧货场界面硬编码了 GLFW（窗口与输入库）的左键编号 0。旧画面还把点击动作写入绘制过程中的临时列表，使输入依赖先绘制。
- 修改：八种语言补齐同名物品键。手持任何铁轨方块点货场顶面时允许正常放置。标签和物品格用与绘制一致的坐标计算命中，优先处理自身点击。分类只保留类别和已有物品／全部物品下拉菜单，已有物品读取当前车厢规则。运行时根据生效线路的货车厢数量自动选择库存方式，保留旧存档的设置字段以兼容读取。
- 涉及文件：十版的 FreightYardScreen（货场界面）、FreightNetworking（货场网络处理）、FreightYardService（货场服务）、八语言资源，以及共用分类与命中规则。
- 回归验证：点击边界和分类筛选单元检查。26.3 独立客户端使用实际界面输入，在首次绘制前点击车厢和物品，核对发出的请求。独立服务器使用实际铁轨物品放置并执行货场筛选请求，再走真实装卸和保存重载。
- 防止复发：对新设备同时检查方块和物品名称。交互回调先区分放置与打开界面。客户端真实输入检查应覆盖物品格及车厢标签，服务端检查再覆盖实际规则更新。

独立客户端验证中已尝试失败的启动方式：Windows 启动器参数文件使用 UTF-8 时把中文路径读成乱码，按本机代码页写入后恢复。26.3 主菜单尚未绑定物品组件，直接创建物品堆栈会报错，名称验证改为读取真实物品的描述键并通过已加载的客户端语言解析。游戏内库存和装货仍在独立服务器流程验证。

26.3 使用游戏提供的鼠标左键常量。核对了 26.1.2、26.2 和 1.21.11 的原生按钮仍使用编号 0。不要把新版输入编号统一套给旧版。

最终结果：共4549项通过。[分版结果](../十版货场交互与分类修复_0.2.42-test14.md)。
