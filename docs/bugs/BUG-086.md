# BUG-086：test5十版本界面、Jade与构建接口适配

项目根目录同本仓库Git根目录。分类：版本接口、客户端生命周期、Gradle缓存。只记录本轮当前仓库的实际适配，不引入其他项目BUG记录。

## 原因与修复

- 1.20.1使用旧EditBox（文本框）构造与三参数滚轮回调；1.20.4及早期1.21.x必须等Screen.init（界面初始化）后才能创建使用font（字体）的文本框。恢复各版已有initialName和延迟初始化方式，保留原字体生命周期测试。
- 旧界面已验收透明背景绘制，不能直接用26.3渲染代码覆盖。分别保留renderTransparentBackground及各版renderOutline/submitOutline/outline和drawString/text等接口，未弱化正确测试。
- FontDescription（字体描述）在1.21.10接受ResourceLocation（资源位置）作为Resource描述的参数，1.21.11及26.x则使用Identifier（标识）；更早版本直接接受ResourceLocation。全部复用固定字重500的同一字体资源，许可证保留，不重画。
- 1.20.x不能调用Java21的List.getFirst；保留Java17兼容访问。原BUG-073的队列清理修复和超过140格回归保持。
- 旧Jade只允许以BlockEntity（方块实体）注册服务端数据，道岔没有方块实体；直接复用26.3的Class<?>注册失败。旧版改为本模组的请求/响应同步设备名，按目标请求位置校验距离和区块已加载，250毫秒节流，断线清缓存；不安装Jade时没有请求。新Jade继续使用其原生服务端数据接口。
- 旧Jade常量类名Identifiers，新版为JadeIds；最终使用稳定的jade:object_name资源标识，避免类名变化。1.20分离main/client（通用/客户端）源码，主插件入口不能直接编译引用client源码，改为只在registerClient阶段反射加载客户端provider，不导致独立服务器缺类。
- 1.21.8服务端玩家位置接口为level()，不能从旧版直接沿用serverLevel()。其余版本按既有成功接口保留。
- 1.20.x Loom（构建插件）1.6的缓存曾出现Failed to read tiny jar info（无法读取JAR映射信息）与失效锁，离线重建又缺intermediary（中间映射）缓存。保留失败日志，使用原指定Java17、真实目标版本，并在需要补依赖时允许联网重建。没有删除游戏文件、跳过测试或修改用户存档。后续旧版构建优先顺序执行，避免与旧缓存诊断争用。

## 失败方案

不得重复：用26.3的客户端构造、字体、Jade方块数据接口原样覆盖旧版；在main源码中直接引用分离client实现；用新版集合接口编译Java17；缺映射缓存时反复离线重试。相关日志在evidence/BUG-086及版本构建日志保留。

## 验证与风险

实际原生界面验证已分别在1.20.4、26.3通过六项状态回调检查，并人工查看截图：无默认、手动按钮禁用、选择后启用、自动独立、重开清空选择、车辆列表旧线路信息。截图和结果在`docs/验证截图/0.2.42-test5/mc<版本>`。

关机脚本路径预检发现`Split-Path -LiteralPath ... -Parent`参数组不兼容；改用已存在完成标记的`Get-Item -LiteralPath`取得目录，避免中文路径及通配符解释。脚本只在完成标记核对后创建唯一请求标志，不设置循环或开机计划，不使用强制结束参数。

Windows原生启动另遇命令行超过32767字符（WinError 206，路径或名称过长）。已尝试失败：将Java17运行参数文件直接写成UTF-8；Windows版Java17启动器在虚拟机设置生效前按系统代码页读该文件，中文路径因此乱码并找不到游戏。最终仅Java17的临时运行参数文件使用GetACP所示系统代码页，javac参数文件、源码、配置、日志仍显式UTF-8；长参数用参数文件传递，路径正确引用。已在当前真实中文路径成功启动1.20.4客户端，不以英文路径通过替代验证。实现位于`tools/preview_release5.py`。

十版分别构建运行包与源码包，旧生命周期、透明背景、网络与保存测试必须保持通过；独立服务端在没有Jade的情况下启动并完成检查。可选Jade编译件只用于接口适配，不能作为运行包嵌套依赖；当前没有安装Jade的游戏实例不擅自安装第三方模组。实际客户端截图按版本分别保存，其他客户端仍待用户实机确认，不能以单版编译代表所有版本。
