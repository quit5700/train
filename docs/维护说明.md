# 后续修改与组件扩展

当前Git（版本控制）根目录就是“最新正式源码”，远程仓库quit5700/train。本次清理由用户明确授权，只保留最新正式工程、正式交付和共享依赖，不再保留本地历史测试工程。Git远程已有历史提交不强制重写。

每版versions/0.2.42/mc<游戏版本>均含Gradle（构建工具）配置、启动器、src/main（公共逻辑）、适用版本的src/client（客户端）以及src/test（回归测试）。26.x的客户端源集采用该版已验证的构建安排，勿直接套用旧版API（接口）。先读docs/PORTING_NOTES.md及当前项目docs/bugs/BUG_INDEX.md，只打开相关缺陷详情。

fabrictrain包下route负责线路和路径，power负责真实供电，depot负责发车及回收，train/entity/offline负责列车实体与后台进度，freight/cargo负责货场、分类与卸货，network负责客户端与服务端消息，registry负责注册。stationaccess包下是合并后的通行与票务功能，实际类名以各版源码为准。客户端界面仍按已验收样式实现，不因业务更改重画界面。

新增方块先给游戏模型与物品图标预览，用户确认后再做；已有定稿素材在design内保留，实际模型和材质以各版本src/main/resources/assets为准。定稿图标字节不变。所有显示文字使用翻译键并保持八种语言键和参数一致。生存合成、工具耐久和创造模式差异须按既有要求验证。

库存、车厢和车票余额等持久化修改必须添加相关自动回归，并用退出后的同版存档副本实测；禁止拿高版本存档直接覆盖低版本。真实乘坐不可切后台或强制下车，到站、卸货及回收只能结算一次。供电与线路合法性分开，没电停车、复电续行。未经本轮授权不调整这些功能。

本次保留的tools/diagnostics为当前维护用诊断源码，不是打入运行包的测试模组。原生图标核验：python .\tools\native_icon_check.py --mc 26.3。界面流程：python .\tools\native_icon_check.py --mc 26.3 --ui --world-copy '<同版已关闭测试存档路径>'。工具自动复制存档，仅运行独立副本；需本机Python（解释器）的psutil（进程库）、匹配JDK（Java开发工具包）、对应真实游戏实例及依赖。

共享依赖保存在H:/CodexWork/q5-gradle-cache与q5-settings-gradle，不因清理临时副本删除。outputs下的两个链接指向共享缓存中保留的原生依赖，映射见共享依赖保留.json。重新构建时若有依赖缺失，允许正常下载补齐，勿把全局清缓存当常规修复。

正式发布只做版本同步、定稿图标与维护工具整理，没有改动生产Java（爪哇）代码。后续BUG（缺陷）记录必须在本根目录内新增，记录根因、失败方案、修改文件和实际验证，不把其他项目记录混入。
